# 回收厂玩法重构计划

依据 [v0.9 原始设计案](Baka回收厂%20游戏设计案%20v0.9/Baka回收厂_六阶段工业配方与数值设计_V0.9.txt) 与同目录结构化 JSON。原始文件作为设计输入保留，实际规则与偏差在本文记录；不恢复已删除的旧路线图。

## 网页挂机适配

- 游玩引导采用开放任务，配置源 docs/quests.json 独立于原案，以导入器解析既有道具名和配方 ID；当前 P1 九项按用户顺序排列，含 WH 真实自动化入库及制造流水线机械手（I0060，原机械启动套件）。p1_free_hands 领取机制奖励后开放仓库递归订单与 P2；旧 P2 以上档保留阶段，不补发物流奖励。物品奖励不计入制造里程碑，也不用于工业闭包审计。详见 quests.md、warehouse-orders.md；材料提交等未来目标仍需真实条件与消费规则。

- 机械手订单使用已开放六类工作室配方，递归回溯、整批进位、复用副产物；不调用地图机器或免费拾荒。一次预留现有材料，独占原有队列，完成后交付全部剩余物料；取消只退当前实物。目标最多 1000、256 工序 / 10000 批，规划有深度与访问预算。当前工业静态闭包假设可领取机械手机制奖励，仅验证可制造性，不验证玩家已领奖或布局运行。

- 保留垃圾包唯一无限源头、固定整数配方、六阶段里程碑、55 种机器和副产物阻塞。
- 工作室提供初始 M01/M02/M07，共用一条手工加工队列；手动拾荒每次获得一包垃圾。地图设备连续生产，玩家选择配方、投料和收取；物流设施逐步替代手工搬运。
- 游玩便捷适配：工作室按手动分拣 / 铁砧 / 手工工作台分组，首次真实制造 M03 / M04 / M08 对应设备后永久开放其工作室配方，不必安装；解锁复用累计 crafted，不新增消耗或赠送设备。仍共用一条队列并保持配方材料 / 批量守恒，手工每批耗时为 `max(1, floor(duration_ms / 2000))` 秒，即原配方秒数一半、向下取整且至少 1 秒；地图机器继续原工时，导入器不改原 duration_ms。旧队列保留进度，超过新工时时下一运行 tick 最多结算当前一批，不补算多批。热能设备及其余机器仍需现场生产。批数输入超限自动回填库存可加工数（最多 100），Worker 仍复核并预留；仅设备子分类在工作室滚动区内吸顶，垃圾堆正常滚动，原料 / 产物卡分别显示当前分仓库存与每批需求 / 产量。
- 设备道具和安装实例分离。安装消耗道具，拆迁完整返还设备与缓存；避免网页中试摆、误操作造成不可逆损失。加工中原料只结算一次，切换配方不得生成产物或丢失原料。
- 机器采用配方所需缓存，最多 12 种、每种 100；基础分拣有 9 种产物，不能继续套用旧 4 格上限。流体采用独立容器和运输规则，禁止带上运输散装流体。
- 各阶段使用轴功、热能、流压、电力；每秒整数能量账本，不按每个配方重复收取燃料。分馏启动保留蒸汽替代动力。缺能保留进度；先实现整刻停机和公平分配，再根据实测调整限电曲线。
- 地图继续使用 DOM/CSS/SVG、固定三栏、1 TPS 和普通/节能共享动画。高等级带以批次表示吞吐，不增加 tick 或逐件 DOM 数量。
- 一个 Worker 管理全部厂区；未显示厂区也推进，页面后台/断网则全部暂停。分厂通过显式物流任务转移，禁止机器直接读全局仓库。
- 首版无随机磨损、随机泄漏、不可恢复损坏或不可达的真实 3D 楼层；巡检/维护针对实际堵塞和供料事件。样本必须消费真实作业凭据，不能空转刷出。
- 智能机器人为游戏内确定性调度，不接外部 AI 服务；终局保留效率与产能挑战。
- 旧测试工厂采用无损升级，旧物品/实例保留兼容，停止作为新游戏内容销售；不清除账号、本地或云存档。
