# 生产、库存与物流

## 仓库终端

领取“舱门过于拥挤”后，各厂可独立付费增设固体终端；取货 / 存入累计配额 P2 为 2/1、P3 为 4/2、P4 起为 6/3。取货单朝向，1～2 种固体在成功后轮询，每秒最多 1 件；缺货 / 拒收跳过，堵塞保留库存与游标。存入四面接货并加入唯一总仓库和实际自动入库统计，无独立库存。两类终端可移动、不可删除，安装和物流都由 Worker 原子提交；费用、兼容和验收见 [仓库 IO](warehouse-io.md)。

## 固体物流的候选物品与阻塞

OUT / IN、初阶自动投料机、各级投料臂 / 柔性节点和机械分流器共用 `local/logistics.ts`。从箱子或机器产物格取货时，先按自身 / 分支过滤收集全部旧库存候选，再依次检查目标白名单、所选配方或燃料通道、剩余格数、该物品 100 件上限及本刻已预留量。某个候选被拒绝或满载时继续尝试后面的物品，不因第一个物品阻塞而停止；明确指定过滤的设备不会换成其他货物。

例如 R1024 耐火砖使用砂粒与陶瓷粉，炉内砂粒 100、上游箱内先放砂粒 100 再放陶瓷粉 100，未设置过滤的投料机应跳过已满的砂粒，输送陶瓷粉；炉体仍需实际燃料才能生产。每个物品仍只占一格，格数满但已有同种物品未满时可继续补入。

每条路线的物品候选作为同一组参与原有 tick 轮换，不因来源品种多而增加轮换权重。一台端口 / 投料机 / 分流器一次最多成功一个定义批次，成功后才进入原冷却间隔；分流器仍按既有分支轮换及过滤选择可行分支。不新增物品优先级、物品轮换游标或存档字段。

向已有载荷的传送带预留时，必须确认旧载荷能在同一批完整离开，部分提取不算腾空。若预选路线不能满足该依赖，排除该路线并从相同旧库存重建预留，允许设备改试其他分支，也让其他设备使用被释放的来源 / 容量。没有其他提取路线的堵塞带链会一起排除，避免逐格反复重建；完整同容量闭环仍可统一移动。最终方案确定前不扣物品、不收货、不计冷却、不发成功收据；最终仍统一先扣后收，新到物品不能同刻再跨格。不承诺复杂竞争网络的最大吞吐量。

修正范围及保留的约束：

| 设施                           | 行为                                                                |
| ------------------------------ | ------------------------------------------------------------------- |
| 固体端口 / 投料机 / 固体分流器 | 可在同一动作内尝试后续可运输物品 / 其他可行分支，保持定义批次与间隔 |
| 传送带                         | 单一载荷，不能换货；保留堵塞、整批腾空、拆批和闭环规则              |
| WH 输出                        | 每面明确指定物品，不能为绕过阻塞改送别的库存；输入过滤照常检查      |
| 物料管 / 罐                    | 只存一种介质，保留指定过滤、旧容积预留和禁止混液                    |
| 分液阀                         | 满分支继续按权重等待，不改成跳过该分支破坏配比                      |
| 机器人                         | 运输任务明确指定货物，满载 / 不匹配继续等待，不擅自换任务物品       |

## 开发者模拟倍速

正常游戏默认 1 TPS，1 tick 代表一秒游戏时间。开发者可在“开发者工具 → 功能测试”输入 1～60 的整数 TPS，点击“应用 TPS”或“恢复 1 TPS”。仅改变 Worker 定时调度间隔 `1000 / TPS`，每次唤醒最多执行一次现有 `stepWorld`：配方整秒、能量 kJ、物流批次 / 间隔、机器人和主厂唯一手工队列仍按原 tick 原子转换。10 TPS 表示目标每真实秒推进 10 秒游戏逻辑，不缩短配方定义或跳过结算。

速率由 `local/tickRate.ts` 统一验证，主线程与 Worker 都拒绝非法 / 小数 / 非有限输入。该参数属于当前页面，刷新、换账号或关闭开发者工具后恢复 1；不进入存档，既有 `simulation.tick_rate` 保持 1，不改格式、规则版本、HTTP 协议或数据库。暂停时不能通过界面调整；切 Tab / 厂区不改变已选速率，暂停恢复继续使用本页速率。

在线许可、约 10 秒心跳、最多 30 秒许可、30 分钟云备份和页面生命周期仍按真实时间。后台、休眠、断网或许可失效停止，不积攒定时任务，不循环追赶；重设速率不会直接推进 tick 或重置生产进度。单 Worker 同步推进全部厂区，实际速度受模拟、消息传输和保存负载限制，60 TPS 为可设置上限，不代表已实测达到该性能。自动本机保存仍为每 5 tick 并沿用合并在途请求的机制，倍速会增加保存频率；无离线补算。

## 可选机器占地

36 台审查候选机器支持 1×1 / 2×2；实例 size 缺省 1，x/y 是左上角，2×2 向右及向下覆盖四格。尺寸不增加容量、工时速度或设备数量。投料机 / 管道可从八个四向外邻格访问同一实例的缓存，继续统一预留再扣收，不生成额外副本；能源扫描整条选定边但只接一个对应网络，不桥接网络。机器人将四格全部视作障碍，从八个外围可达空地工作；有效蓝图保留同样四格，编辑 / 部署 / 过境落点共同避让。详见 [machine-footprints.md](machine-footprints.md)。

## 唯一全局工作室

P2 任务的 factory_produced 只在地图机器实际完成配方后逐物品增加，warehouse_received 只在固体 / 流体物流或机器人正常卸货入 WH 时增加，进度逐物品取两者较小值；工作室、手动收取、奖励和取消退款不计。轴功整批完成、蒸汽实际入储压罐及发条车成功卸完携货另记事件，扩建成功立即同步厂区数；账本全世界唯一，随快照 / 存档保存。详细判定、旧档边界与奖励见 [quests.md](quests.md)。

任意厂区的 scavenge / workshop / order_workshop / cancel_workshop 均经 Worker 串行路由到主厂唯一 industry.workshop 与总仓库。只有主厂每世界 tick 推进一次，分厂不持有额外队列 / 行业状态；跨厂查看、再次开工、取消和保存均操作同一份状态。队列占用拒绝第二次开工；预留、逐批结算、取消剩余实物与失败原子性不变。此为移除界面和入口位置限制，不增加并行工作室或存档字段；地图垃圾提取口仍只允许起始回收场。

## 共用总仓库

所有厂区 WH 共用同一总库存，任意 WH 入库后任意厂区可建造、补料、收取、拆迁回收、下单 / 取消订单及使用实际机器人道具。机器缓存、箱内库存、带上物品、管内流体、机器人携货和订单预留仍为独立实物，不因共用仓库提前入库或复制。机器仍需投料机 / 传送带 / 管道或手动补料，WH 各自的启停、过滤、方向与输出额度保持。机器人真实动作、跨区 8 tick 行程及作业凭据规则不改。

一次世界转换克隆总账，主厂和各分厂顺序使用更新后的同一库存，争用最后一件只能成功一次，不出现负数或重复占有。分厂持久化 warehouse={}，当前视图显示主厂总账；不会为每个厂区保存一份相同库存。旧规则 1/2 的各分仓仅在完整校验后的读取升级中相加，改存规则 3；缓存 / 携货 / 队列原料不合并，总和溢出拒绝并保留原档。新版本拒绝重复的分厂仓库，刷新或云恢复幂等。

开发者工具的“仓库下单始终可用”只覆盖下单入口 / 运行层的任务领奖条件，不参与 expectedStage，也不生成任务奖励或解锁地图配方。配方可用性、原料预留、逐批工时、取消守恒、联网暂停与全世界唯一队列独占保持；设置默认关闭并保存。未领奖且订单尚在执行时须先完成 / 取消后再关闭，避免生成失去权限的队列存档。

开放任务依据实际获得、制造、工作室完成批次或自动化 WH 成功入库事件判定，账本只存主厂 industry.quests。领取无需提交材料，物品一次存总仓库；跨厂不复制、重复 / 溢出整笔拒绝，物品奖励不计制造量或里程碑。P1～P5 仅在阶段终局任务完成并领奖后推进，不再由制造里程碑推进；里程碑保留真实制造与配方前置。终局需完成同阶段其他任务至少一半（向上取整）才开放，已达成未领奖也计数，隐藏目标不能直接领奖。P1 为 4/8，领取 p1_free_hands 同时开放仓库订单。P6 主目标仍为首次制造智能机器人，无 P7。旧档先验证旧阶段，再只补认已跨过阶段的终局并写 stage_quests_version=1，不退回原阶段、不补普通任务或奖励；后续统一走新规则。规则见 [quests.md](quests.md)。

仓库订单只使用已经开放的六类工作室配方，可递归整批加工并复用副产物。确认时一次预留所有所需仓库存量，顺序工序与私有物料存入唯一手工队列，逐批按手工工时扣实际原料 / 加实际产物；中间物料不进入可重复使用的公共仓。最后一批完成后一次交付全部余料 / 成品；取消返当前私有物料，已消耗的原料不再返。不得调用地图机器或免费取垃圾；数量 / 规划有上限，完整边界见 [warehouse-orders.md](warehouse-orders.md)。普通手工加工与订单互斥，原有联网许可、暂停和不补算规则保持。

物品发现记录 `industry.discovered_items` 用于图鉴灰显和首次获得任务。拾荒、提取口实际产出、制造成功或领取物品奖励才新增，消费后保留；记录本身不授物品、产量或里程碑。记录全世界共享并保存，旧无字段存档在读取时从制造记录和现有库存 / 实物补记；不能把可查看资料、配方选中或进入阶段当作已获得。

## 闭包、诊断与终局（F）

导入时静态检查阶段 / 里程碑、实际设备道具、材料、燃料 / 轴 / 线 / 液压介质与蒸汽管道、兼容补能站和匹配作业机型 / 摄像头。未知条件拒绝，真实作业能力只表示可搭建可反复运行的取送或异常 / 备件路径，不赠送凭据或存货。分析证实一个启动路径存在，不证明库存批次数、布局、最大吞吐或玩家已完成作业；报告见 gameplay-data-audit.md。

P4 新增 `web_cable_start`：M08 手工装配台，粗铜丝 5 + 绝缘胶 2，15 秒得到绝缘线缆 2，要求 P3 电气化建设包里程碑。解除“线缆需电，而电需线缆”的首网依赖；不免费送导线、不重复扣原配方，R4008 / R4009 保留为通电后的高效路径。原案 JSON 不改，导入脚本是适配源。

诊断中的缺料为当前厂设备缓存缺口，并显示总仓库；仍需实际向设备补料。产物 / 副产物检查整批容量与种类；工作条件检查可消费账本；能源看已付工作能量 / 实供功率及真实燃料，正常耗尽当刻工时信用但已经足额供能不能误报缺电。禁用设备不列为异常。诊断提示不生成机器 incident 或真实凭据，新装空机的“缺料”提示不能用来刷巡检。

名义产出 / 消耗按启用设备的所选配方持续满速计算，不保证实际可达。独立观察窗口最多 60 个实际运行 tick，制造记录包含工作室与全部厂；固体 / 流体统计为逐格转移量，不能当作净物料生产，机器人只统计成功交空载荷的趟数。暂停不加样本，重读 / 编辑不重复结算，刷新 / 恢复云档清空窗口，不清除永久行业进度。

P6 是阶段，首次制造智能机器人（六阶段最后里程碑）才完成主目标；部署 / 后续消耗本体不撤销该成果。首次制造可扩展智能工厂许可证得到沙盒目标反馈，不赠新厂或资源。许可证是可持续优化目标，不改变已实现的 P6 100 厂区上限；多格蓝图 / 3D 楼层等原案不适用部分仍不在范围内。

## 机器人状态与授权整合（E2d3 / E2e）

归属、当前位置、任务取送端点、巡检 / 维护现场、施工目标和过境落点所在厂区均为必需授权。管理界面锁定使用中的授权并说明原因，直接提交非法撤销也由 Worker 原子拒绝；暂停不解除保护。取消后仍使用的当前 / 过境 / 保留现场元数据继续受保护，完整返站且任务清除后才撤销闲置授权；不会把只曾访问过的厂区永久锁死。实际归属站邻格且无任何任务 / 携货 / 过境 / 返程状态才允许召回。

静态可达但被机器人占格堵住，显示“占格等待”；建筑、蓝图或 WH 允许端口导致无路，显示“通路不可达”。只有有限完整行程超过储能上限才显示超范围，不能把无路当作续航不足。无路 / 占格等待不耗行动能量；携货 / 工时保留。世界暂停优先显示在线许可暂停，个体暂停明确说明启用后继续；对已暂停机器人取消任务仍保持暂停，不强行启动回收。

返程说明区分取消、实际完成、能源保留中止及目标失效；携货先实际回 WH，再回站，未用维修备件仍在实际归属站退款。能源返程中保留的运输 / 现场任务补满后可继续，施工中止仍取消原蓝图；自主调度启用时完成返站后可能分配新任务。地图与列表只展示这一状态，不自动扣货、换目标或赠能。

路线仅为当前快照下的一段实际寻路结果，按空地、蓝图、机器人占格和 WH 端口判断；跨区先显示当前 WH 路段 / 过境落点，不绘制虚假连通的跨厂直线。选择、筛选、查看路线不生成 revision、收益、凭据或存档字段；切换厂区沿用原世界动作。暂停 / 后台 / 许可失效保留工时与载荷，恢复仍无离线追赶。

## 蓝图施工与在建回收（E2d2）

仅智能机器人接受显式施工，一台同时一张单格蓝图；多台可并行。指定已授权厂区、设备、空格、方向和可选已解锁配方。必须实际停靠归属补能站且储能补满，归属 WH 有 1 个已制造的安装道具。先验证阶段、配方门槛、源头数量、格位、路径、足够往返储能及其他机器人的安全返程，再原子扣 1 道具入 cargo；不重复扣制造设备的原料。从总仓库扣除且不因切厂复制道具；跨厂仍需经过 WH 与 8 tick 付费行程。

活动蓝图格位视作障碍，不能行走、部署、移入 / 放置建筑或作为过境落点；仍需留出邻格工作点。源头蓝图只在起始厂 y=10，并连同已安装 / 其他在建源头共同占阶段数量。设备 ID 与实际 / 在建实例冲突会拒绝。普通机器人不可施工，旧测试设备 / 固定 WH 不可作为蓝图。编辑不能让蓝图越过数量或位置限制；新障碍不能增加到机器人无法承担的返程成本。

每次移动 / 过境 / 现场工时付 1 kJ；实际到达邻格后连续累积 10 个有效工作 tick（可暂停后继续），不预演安装。工作前始终保留携货返 WH / 返站与余量。第 10 tick 原子将 cargo 转为建筑，方向 / 可选配方生效，缓存 / 流体 / 储能为空，从下一 tick 才参与生产。完整设备不再存在于机器人或仓库；施工日志不计运输次数，也不生成巡检 / 训练 / 视觉凭据。

取消或能量中止立即释放蓝图格位，保留同一 cargo 与施工元数据，沿实际路径经归属 WH 卸货再回补能站，至此清除施工；在途过境先走完，不瞬移退款。仓库数值已达上限则保留 cargo 等待，不溢出或丢物。暂停、后台 / 断线许可失效不推进位置 / 工时；取消不自动恢复原蓝图。中途禁止召回、另派运输 / 维护 / 施工或卸下附件，不能撤销施工 / 当前 / 过境所需厂区权限；返站后可重新指派。拆除已完工设备沿用真实设备 / 库存回收。刷新 / 云恢复保留工作进度、携货、过境和回收阶段，旧档无字段即无施工任务。

## 智能自主派单（E2d1）

仅智能机器人可设置 autonomy，默认关闭，可分别授权配方补料、巡检、消耗备件维护；不能改变其 allowed_zones。空闲且实际停靠归属站时，至多每 5 个运行 tick 评估一次新任务。目标按设备优先级 1 最高、同级依据保存的 tick / 稳定 ID 轮换，机器人也按优先级 / 同级轮换竞争。无符合条件的机器人时跳过目标列表；每世界 tick 共享 2,000 次候选 / 来源访问预算，未评估的机器人留待后续轮询，不用无限循环尝试解开拥堵。预算与路径仍保守，百厂 / 五百机器人规模尚未实测，F 已接入世界端点 / 承诺索引及增量快照，性能仍需实测。

补料只补目标当前配方一批所缺输入，数量扣除已有运输任务尚未交付的需求，最多实际载重；还会扣除来源 WH 已承诺但尚未装走的库存。供货只能来自授权厂区的共用总仓库，WH 必须启用、配置该物品输出面且路径可达；不直接从总仓库远程给机器加料，也仍需授权对应 WH 端点并实际装卸。首次派单仍需归属站补满，跨区 / 装卸 / 能量 / 容量 / 满载 / 返程沿用 E2b。新到机器输入在实际生产完成前保留，避免反复补足正在加工的一批。

巡检 / 维护复用 E2c 的真实持续异常与在场工时，同种现场任务被另一台非返程机器人处理时不重复指派。维护只用总仓库的实际备件，缺件或无固体阻塞则跳过，可继续考虑其他目标。失败提案还原机器人和总仓库，不留下虚假任务、被扣物品或半次操作。

关闭自主派单只阻止新指派，已运行的任务继续；立即停工使用暂停机器人，携货取消仍须实际返站。授权撤销不能绕过现有任务 / 现场 / 过境保护。保存最多 20 条派单 / 配置 / 等待 / 施工日志，连续相同等待不刷记录；日志不生成凭据，也不调用外部 AI。配置、下次检查 tick 与日志随世界保存，恢复不重建第二份任务。当前自动补料仅覆盖所选配方输入；燃料走显式物流。E2d2 施工由玩家显式指定蓝图，不能据自主按钮宣称自动整厂规划已完成。

## 真实异常、现场维护与训练（E2c）

`incidents.ts` 在各厂生产 / 物流结束后记录实际异常：已成功加工过的机器缺料、具备原料但实际缺能、配方产物容量不足、流体节点满容。新装空机不产生缺料证据；禁用、无配方和缺少训练凭据不是巡检目标。不依据保存的状态文字或画面授奖。每个连续异常保存 kind / since_tick / inspected / maintained，持续至少 5 个运行 tick 才能指派；暂停、后台和断网不累计工时。异常消失 / 改变才开启新一轮，原地刷新 / 移动 / 反复读快照不能重复记账。旧机器缺省批次数为 0，下次实际生产后才能进入运行后缺料诊断。

巡检机器人或智能机器人从归属站出发，走 E2b 实际通道 / 过境，到现场邻格完成规格工时（每秒 1 kJ），完成时再次验证同一轮异常。成功后标记 inspected 并生成 1 巡检凭据；多个巡检机器人竞争也只能记一次。途中现场已恢复、端点删除或取消则实际返站，不奖励。

维护机型与智能机器人可以清理固体产物积压。在归属站由玩家从总仓库装载 1 真实维修备件箱，独立保存于 service.parts；到现场完成规格工时后，从实际阻塞所选配方的一种固体产物取最多一载重，消耗该箱，再携 cargo 走回归属 WH 卸货与归属站。不是赠送材料、随机磨损或用备件凭空补能 / 补料；液体积压只巡检，仍需真实管道 / 液压搬运疏通。多种副产物可能需要继续清理：同一异常可再做实际清理并消耗备件，但 maintained 凭据只记一次。若取消、异常恢复或目标失效，未用备件保持在机器人上，实际返站后才退回；仓库达到整数上限时等待，不丢弃或瞬移。维护成功后取消返程不撤销已经完成的真实作业。

P5 可在空闲归属站安装 1 实际摄像头组件；同状态重复安装不再扣物品。安装后每次有效运输交空载荷、首次巡检或首次维护同步生成 1 视觉凭据，不凭停靠、充能、截图或空转生成。卸下与安全召回返还同一组件，不能在途中卸下。摄像头是已安装附件，不占运输载荷。

主厂唯一行业进度保存 work_receipts，按机器人 ID / 本体物品 / 类别合并计数、记录 last_tick，每行最多 10,000 次、最多 1,500 行；达到上限只丢弃新凭据，不赠物或回退作业。搬运 completed_tasks 仍只是累计显示，不能反复兑换。R5048 / R5049 按原案机型集合分别需要 40 次搬运 / 20 次巡检或维护凭据，R5050 需要 30 次带摄像头的有效作业凭据。机器人必须仍部署且启用；视觉兑现还要求摄像头仍安装。暂停后凭据保留，召回清除该实体未使用的凭据，重新部署不能继承旧 ID 的工作。

训练原材料、输出、工时、门禁和能耗保持原案。productionReady 只探查，缺凭据停机、不申请新工艺功率；完成时再次验证并原子消费原料 / 凭据、交付产物。换配方、满产物、取消或缺能不消费凭据。根厂与分厂依次使用同一份更新后的账本，分厂仅临时读取全球在岗机器人，不保存副本，多台 M46 不能重复领取。旧无凭据档缺省空账本，无数据库迁移。两端校验数量、类别、已知机型、唯一行、时间、实际附件 / 作业 / 保留备件结构，不证明单人行为真实性。

## 实际路径与跨区运输（E2b）

`local/robotRoutes.ts` 以地图内空闲地面 BFS 寻路，所有建筑（包括带、线缆和管道）占格。机器人每 tick 最多走一格，不能穿越建筑、重叠、交换占格或同刻再装卸；同级按 tick 轮换、优先级 1 最高。目标为设备邻格，WH 取送选择实际允许该物品的面。当前采用保守避让，窄通道和被停靠机器人堵住的站口可能等待，需要玩家留多格通道；不承诺拥堵无死锁或最大吞吐。

搬运 / 智能角色可设置一种物品、单趟数量（不超过实际载重）、来源 / 目标、输入或燃料用途及是否循环。普通电动、分拣及发条车只运固体；液压搬运机器人和智能机器人采用密封载舱，可运单种整单位流体，不能混液。巡检 / 维修角色使用 E2c 专属任务。来源只取机器产物、箱子库存、单介质容器或 WH 实际库存，绝不提取机器输入 / 燃料。机器交货按当前选中配方或真实燃料表接收，缓存容量不变；罐按介质白名单 / 过滤与实际容积接收，外部装卸不要求生产机器有电。

每次到达端点先支付规格 `action_ticks` 秒的装卸准备工时，再按每 tick 一个装卸行动转移（普通端点最多一载重，WH 输出每面 1 u）。走格、跨区行程的每秒、准备工时和成功装卸各消耗 1 kJ；等待无路、空源、满仓或拒收不烧机器人能量。离开端点重置准备工时。出发在归属站补满能量；保守估算完整行程及携货返仓 / 返站费用，超容量拒绝指派，途中保留返程能量，不足则携货送归属 WH 再实际返站补能。站点仍只发放已付 kJ，过境中的旧坐标不能领取补能。没有新增免费燃料或液体。

跨区须显式授权且规格允许：先走到当前厂 WH 邻格，进入 8 tick 行程，每 tick 消耗 1 kJ，结束后只在目标厂 WH 的空邻格落地，再走到交货设备。离站 / 落地各占一个逻辑行动，不同厂库存不会因切换而变化；未落地或未完成装卸时货物仅在机器人 `cargo`。落点被机器人占住则等待，不瞬移到别格；过境落点禁止建造。机器和所有其他厂仍按单 Worker 同步推进。空分厂的首批设备通过 WH 收到实际道具后才能安装。

固体 / 流体自动物流先结算，机器人随后读取最新库存并顺序原子扣收；多个机器人不能重复取同份物品或挤爆缓存。WH 固体输出与机器人共享每面每 tick 的 1 件额度；流体目前只有整座 WH 的流出合计，没有逐面收据，任一自动流体输出时机器人保守让出该 WH 的本刻输出，保证不超额，后续可细化公平性。机器人货物不进入固体带的 `transfers`，不生成重复结算动画。

取消或端点删除后保留实际货物，先按路径送回归属厂 WH（应急返仓可绕过其输入面配置），再停靠归属站；取消不计完成次数。成功交空一次真实载荷才累计 `completed_tasks`；E2c 另外生成可消费凭据，累计显示本身不能兑换。满载或混液保留货物，腾空 / 改正后继续；暂停保留位置、载荷、工时及过境余秒，恢复不补算。任务、载荷、返程和过境状态随完整世界一起保存，恢复不重新取货。当前位置、任务端点及过境目的地未解除前不能撤销其厂区授权。

绑定站点不可移动 / 拆除；建造和移动不得占机器人格、过境落点或新堵断其返站路径 / 增加到剩余储能无法负担的返程。召回要求实际停靠归属站且无任务、货物、过境或返程状态，避免远程刷回本体。无路或超范围存量不丢失，由玩家调整通道 / 取消返站；不提供免费救援瞬移。

## 机器人本体与补能（E2a）

导入原案九种机器人。载重为 4 / 12 / 0 / 24 / 8 / 12 / 6 / 4 / 32 u；对应动作最低工时 8 / 10 / 30 / 8 / 5 / 2 / 40 / 35 / 2 秒，另加实际路径及转移动作时间。E2a 提供部署、停靠、补能、权限和召回，E2b 加入运输，E2c 加入现场作业与真实条件消费。

部署从当前厂区仓库扣一本体，只可停靠在能源兼容站点的相邻空格。全世界最多 500 台，不重叠、不占建筑格，默认只授权归属厂；跨区能力按规格开启授权，发条与定点分拣角色不能任意扩区。存档将机器人统一保存在主厂 robots，含归属站、厂区、坐标、能源、优先级、启停和允许厂区；子厂不可再次保存一份。旧档缺省没有机器人，不赠送本体。

轴功 / 液压 / 电动 / 智能机器人储能容量分别 1,000 / 3,000 / 15,000 / 30,000 kJ，部署为零。M18 储能 1,000 kJ，网络取能和全站补给各 5 kW；液压补给站复用原案液压工业示范机组，3,000 kJ / 15 kW；电动换电站复用实际道具，30,000 kJ / 100 kW。只将本 tick 实付网络能量写入 station_energy_kj，站满不申请能源或轴损，旧已付 work_energy_kj 转入站储能一次。未付的 powered / supplied_kw 不授予能量。

机器人只从站内已有能量补给，站点总速率共享，优先级 1 最高、同级每 tick 轮换；暂停机器人不再领取，暂停站点停止蓄能和发放。停电后可用已付站储能，耗尽停止，不新烧燃料。电动补能效率 88%，charge_remainder 保存百分之一 kJ 余数，满电丢弃余数；轴与液压用已输出的对应机械能等量补给。

召回须实际停靠归属站，将同一本体返还归属厂仓库，储能与余数散失。绑定机器人期间禁止移动 / 拆站，机器人占格禁止建造；召回后可改站。未绑定站移动保留储能、拆除散失储能并返还实际设备。仓库存量与部署实体互斥，不能一边部署一边用于消耗机器人本体的里程碑配方。Go 与客户端校验容量、站点兼容、位置、权限、ID / 占格唯一及结构；不证明单人产量真实性。

## 能源网络（D1）

所有能量为整数 kJ，1 tick = 1 秒，1 kW = 1 kJ / tick。热炉直接燃烧；轴 / 液压 / 电网仅连接相邻的专用导线格，设备只接一个自动或指定侧，不桥接两个网。M09 / M21 / M28 输出上限 50 / 85 / 160 kW，按真实出功消耗燃料缓存：固燃 1 u 在 M09 为 1,980 kJ，液体燃料在 M21 / M28 为 6,080 / 6,400 kJ。供能不足不满速生产，已付工作能量积累够一秒额定工时才推进；暂停保留，切配方清零此专用能量并保留输入。

负载优先级 1～6，同级 tick 轮换；燃料 / 净水和动力站默认 1，物流 2，普通 3，训练集群 6。轴网活跃时每 12 段向上取整扣 kJ 驱动损耗，输出不足以覆盖损耗时不空烧。启用的动力带 / 投料 / 站点有持续驱动消耗；空闲可暂停。生产机缺料 / 满产物 / 条件不符时不申请能源。

M20 分馏可用液压，也可用高压蒸汽放入独立 fuel，每 u 释放 100 kJ；缺液压部分只扣对应蒸汽，不重复计费。M21 R3012 为冷混配，配方消耗的液体燃料是介质添加剂；R3013 增压明确 20 kW，可由自身燃料供能。至少将 1 u 真实液压工作液从仓库注入 medium，才可输出液压，最多 10 u；闭环介质不按秒凭空耗尽，配方中的污工作液仍真实产生。拆除返还介质，不赠送内置启动液。

电池容量 15,000 / 30,000 kJ，输入 / 输出各上限 100 kW。仅剩余发电充电，88% 转成存量，charge_remainder 保留百分之一 kJ 余数，满仓余数舍弃；不从电池给电池充电，不在同一刻充放。支持自动 / 只充 / 只放 / 保留，reserve_kj 只允许 1 级负载动用。移动保留电量，拆除散失电量、返还设备；已燃烧能量不逆转成燃料。

每 tick 重新建图并清除旧供能许可，保存的 powered / supplied_kw 不能让断网路设备运行；network / powered 为派生显示状态，work_energy_kj / charge_kj / medium 为实际本机资源。P2 新增 web_pipe_early 用手工装配台先造物料管道，原 R3045 继续保留。

## 固体物流扩展（阶段 C）

本节优先于下方保留的旧版单件传送带和无过滤 OUT / IN 描述。

- `local/logistics.ts` 读取本刻生产后库存，预留来源、目标容量与行动次数，解决带占用依赖，统一扣除和接收。新进入带的物品不会同刻再走第二格；竞争按稳定 ID 和 tick 轮换，保守预留不承诺复杂网络的最大吞吐。
- 顶部 y=10 提取口消耗初阶自动投料机，每 10 tick 产 12 包，输出满则保留进度；阶段数量上限 1/2/4/8/12/16，不能移出顶部。
- WH 四面默认输入，支持输入过滤、指定一种输出物品或关闭；输出每面每秒一件，可接相邻带 / 箱 / 机器或投料机。多面争用一起预留，不能负数。关闭或输出面拒绝输入。
- 分拣料箱 8 格、物流缓冲仓 12 格，每种 100；箱内进出使用单份库存，接收不等于入总仓库。支持手动存入 / 收取。过滤限制后续输入，原有物品保留并可输出。
- 投料机以后方取、前方送，支持物品过滤、1～60 秒限速、配方输入 / 专用燃料目标。实际选中配方决定输入白名单；不提取机器输入格。生产机器断电时，外部物流仍可存取缓存。
- M17 / 智能闸门从后方取，轮换尝试前/左/右分支，各自可过滤；每 tick 一个行动，堵塞保留来源，不复制到多分支。
- 手摇带容量 1、每格 3 tick；机械 / 液压 / 电动 / 精密 / 柔性带批次容量 1/2/3/5/6、每格 1 tick；高阶投料臂 / 柔性节点每次最多 3/5/6 件，受真实库存和容量限制。动力现已由 D1 分配，缺能保留货物和进度。
- 带格存一种物品的一个批次，belt.count 缺省为 1。快带进慢带可拆批：来源剩余批次保留 ID，拆出者用有界新 ID。被占用目标带必须同刻整批移出才可接收；满载同容量环可同时移动，部分取走不算腾空。
- 散装流体不能进入固体带 / 箱 / 投料机；工作室、手动搬料和专用管网可操作流体工艺单位。
- 单批次绘制一个小图形；慢带三段连续补间，暂停 / 缺能停止预演。改变过滤或方向撤销旧视觉路线，实际已交付库存保持。

## 回收厂玩法扩展（阶段 A / B）

当前开发范围和剩余任务以 [gameplay-plan.md](gameplay-plan.md) 为准。以下扩展优先于本页保留的旧测试产线规则；尚未实现的能源 / 物流设施在目录中已有定义，不代表已经具备运行能力。

- 唯一新玩法无限源为垃圾包，工作室每次拾取 1 包。初始工作室有 M01/M02/M07，共用一条手工队列；不额外赠送设备道具。
- 首次真实制造 M03 简易拆解台 / M04 手摇破碎机 / M08 手工装配台的设备道具后，其配方可在同一工作室队列加工；按对应道具的累计 crafted ≥ 1 判定，不按当前持有数、已发现或安装实例判定。使用 / 拆除设备不撤回解锁，读档沿用已有制造记录；不赠送设备、不扩大初始 starting_machines、不开放其他机器。Worker 开工及两端存档校验同步使用该条件，未解锁队列拒绝；原材料、阶段门槛、1～100 批及取消守恒规则保持，所有已开放工作室配方共用下述手工工时加成。
- 手工批量加工为同一配方的 1～100 个整数批次，可加工上限为各原料库存整除每批消耗的最小值，再取最多 100；UI 超限正整数自动回填该上限，空值 / 小数 / 非正数不提交。提交时在 Worker 内重新核对并一次预留全部批次原料；共用队列忙碌时不再追加。手工每批耗时为 `max(1, floor(duration_ms / 2000))` 秒，例如原 7 秒变 3 秒、原 10 秒变 5 秒，地图机器保留原 duration_ms。每完成一批才入库并记录制造。取消退还包含当前未完成批在内的剩余原料，已完成产物保留；重复取消不重复返还。队列 recipe_id / progress 与可选 remaining / total 一并保存，后两者须同时存在且 1 ≤ remaining ≤ total ≤ 100，旧单批存档缺省 1 / 1；恢复不再次扣料。加成前队列仍按原工时上界校验并保留进度，已达新工时时下一运行 tick 只完成当前一批，不循环结算 / 跨批追赶。产物 / 累计制造数上限阻塞时保留工时和剩余批次，不提前结算。
- 地图上的新机器必须明确选择 recipe_id，按其整秒 duration_ms 连续生产。新机器输入/输出各 12 格、每格 100，基础分拣全部 9 种产物有空间才推进；原料仍在完成时扣除。旧测试机器维持 4 格。
- 手动“从仓库补足原料”接受目标完整批数（默认 1，含输入缓存已有数量），只扣总仓库与目标之间的缺量。上限为所有配方原料的 `floor(min(每格上限, 已有量 + 仓库可补量) / 每批用量)` 最小值，每格上限最多 100；还需为所有新物品留出输入格，旧配方残留不自动腾空，同种物品不另占格。超过上限的正整数自动按最大可行批数执行，不因越界拒绝；不能补齐一批或批数不是有限正整数时原子拒绝，不部分扣料。Worker 依执行时库存重算，不信任界面上限；旧未传 batches 的操作仍按 1 批。补料不重置当前工时 / 能量，已有超过目标的物料不扣回或复制。可收取全部产物；取回输入或切换配方清零未完成进度，原料不凭空消失。
- 安装消耗对应设备 / 设施道具，科技阶段不符或没有道具则拒绝。移动保持身份；拆除返还设备道具、输入、产物、未燃烧燃料、带上物品。已经消耗的燃料余热不转换回燃料。
- 炉体燃料独立于配方输入：干燥生物质 / 生物炭 / 固体燃料块分别提供 280 / 1650 / 3600 kJ 可用热。仅在有原料且整批产物可容纳时，每工作 tick 按配方 kW 消费 kJ；燃料不足保留进度。禁止将废电池用作燃料。尚未接入轴功、液压或电网的机器显示缺少动力，不免费生产。
- 第一次真实制造里程碑物品即永久记录解锁，不要求反复将许可证作为普通建筑费用；物品本身仍在产物缓存 / 仓库中。
- 352 / 55 / 329 为原始物品 / 机器 / 配方数；另保留 3 / 6 / 3 旧测试内容以无损读取既有存档。旧测试物品与新工业编号隔离，不作为新游戏建造内容展示。

## 当前运行边界

客户端 Worker 承担生产、物流和编辑事务，服务端只处理账号与单槽云备份。当前纯单人玩法，默认信任玩家数值，格式和容量仍需校验。

沿用 21×21 工厂、固定工厂仓库（地图 WH，内部 bus）及现有编辑交互。新架构从零开始，不导入旧服务端工厂；账号和原数据库记录保留。

## 时间和配方

浏览器 Worker 默认每 1000ms 推进一刻，目标 1 TPS；开发者测试可按本文倍速规则调整调度间隔。1 tick = 1 秒游戏时间；生产、端口和带上物品只按整秒结算。心跳和云备份不推进时间；RAF 只补间 / 预演动画。暂停后不补算产量。

| 建筑       | 输入     | 产物     | 时长          |
| ---------- | -------- | -------- | ------------- |
| 采矿机 MIN | 无       | 1 铁矿石 | 1 tick / 1 秒 |
| 熔炉 FUR   | 1 铁矿石 | 1 铁板   | 4 tick / 4 秒 |
| 装配机 ASM | 1 铁板   | 1 齿轮   | 8 tick / 8 秒 |

配方在 catalog JSON 中定义 duration_ms，须至少 1000ms 且为 1000ms 的整数倍（不足一秒或非整秒配置直接拒绝）。当前每种生产机器一个自动配方。之前仅展示的铁板 / 齿轮配方已改为此表，装配机现在消耗 1 铁板。

有原料且产物有空间才推进进度；完成时一次扣除输入、放入产物并清零进度。原料保留在输入格直到完成，其他机器和端口不能从输入格取出。产物满则暂停，无丢弃 / 溢出；腾出空间后继续。产物满时不会不断累计超额生产进度。

## 库存和白名单

生产机器输入、产物各 4 格；每格最多 100，同类物品只占用一个格子。因此铁矿石已达 100 时不能再开第二个铁矿石格。空栈移除后格子可重用。

- 矿机不接受输入。
- 熔炉仅接受 iron_ore。
- 装配机仅接受 iron_plate。
- 产物格不能作为外部输入目标。

默认容量写在建筑定义，由客户端运行层约束，云上传也校验结构和容量。物流设施使用专用容量：传送带 1 件；端口不缓存物品，直接转移；工厂仓库 直接累计至总仓库。它们不使用机器的 4×100 缓冲格。

## 方向和端口

0° 向右，90° 向下，180° 向左，270° 向上；工厂坐标 Y 向上。OUT 和 IN 均为占一格的定向转移器：

`后方相邻来源 → 端口所在格 → 前方相邻目标`

- 来源：矿机 / 熔炉 / 装配机的产物格，或移动进度已达 1 的传送带。
- 目标：通过白名单的机器输入格、传送带或 工厂仓库。
- 每成功转移一件，冷却 1 tick，最快每秒一件；无来源、目标为空 / 满载或白名单拒绝时不扣物品。
- 两种端口采用同一规则。OUT 常用于机器输出，IN 常用于机器输入，玩家可自由混用；端口不能串联成无延迟链。
- 直接相邻的机器不会自行传料。机器与传送带之间必须经过一个 OUT / IN。

白名单拒绝时，端口显示“目标白名单拒绝”，物品仍在来源。多个端口争用同一来源时不会重复拿取；同一目标传送带每刻只能接收一件。

## 传送带与阻塞

每格仅容纳一个物品，进入时进度为 0，此后每刻 +1，到 1 后尝试转移至箭头方向的下一格。可进入下一条传送带或 工厂仓库；机器输入需要 IN / OUT 端口从带上提取。

传送带可从后方或侧面接收，因此可转弯 / 汇入；面对面反向的两条传送带不会自动互相交接。定向端口可从侧面取物品。不同朝向处目前保留各自视觉，不增加弯角素材。

下游占用且无法移走时，物品停在进度 1，阻塞向上游传播。先完成占用依赖规划，再同时移走旧物品并放入新物品，因此连续带链每秒可以推进一格；不会因遍历顺序让同一物品越过多格。满载闭合环可以同时循环；竞争分支按稳定排序和 tick 轮换，优先顺序可变化。

当前公平策略不承诺复杂网络的最大吞吐量；被阻塞的候选会在后续 tick 重试，不会丢弃物品。

## 总仓库与拆除

物品经传送带或端口送入中心 工厂仓库 后，直接计入玩家总仓库。总仓库按物品累计，不使用 4×100 机器格，暂时只存入和查看，不提供取出 / 投料。玩家之间隔离。

拆除建筑时，其输入、产物和带上物品原子回收入仓库。未完成配方只返还仍在输入格的原料，不凭进度生成产物。移动 / 旋转保留 ID、配置、物品与生产进度，不通过拆除重建。

## 存档和生命周期

模拟、编辑和回收在 Worker 消息队列串行执行，成功时统一替换完整状态并递增 revision。IndexedDB 保存布局、机器、带上物品、总仓库和 tick 的同一快照；编辑后立即保存，生产每 5 tick 自动保存，写入失败暂停。

页面关闭、后台、休眠、断网或许可过期暂停。恢复需重新校验在线账号，不执行离线收益，也不补算错过的 tick。独立单刻函数没有时钟和 IO，为后续有上限补算保留入口；本版不增加该玩法。

每 30 分钟有变更则上传唯一云存档，也可手动上传。上传失败不影响本地生产（心跳仍有效时），恢复时只能下载最近成功上传的版本。云数据不是逐秒生产依据，数量与服务器时间没有自动关联。

## 快照与协议

本地 FactoryDetail 包含 revision、布局及 simulation；simulation 包含 tick、tick_rate=1、buildings、warehouse 和 transfers。MachineState 包含输入 / 输出、progress / duration、cooldown、status 和可选 belt；所有时间以秒 tick 计。belt.id 在带间和端口转移时保持稳定。

transfers 是最近 3 tick 的成功端口 / 入库视觉收据，含事件 ID、payload_id、物品、tick 和来源 / 目标 / 可选端口的位置与朝向。只在真实转移后生成，不二次结算。编辑撤销关联旧路线，初次加载和恢复清空历史视觉事件。

上传存档使用 format_version=1、rules_version=1 和完整工厂；base_version 对应服务端云版本。当前每账号一个本地工厂和一个云备份，不自动合并跨设备仓库。JSON 数值不超过 JavaScript 安全整数上限。登录、权限、云版本和边界见 [architecture.md](architecture.md)，API 以 [openapi.yaml](openapi.yaml) 为准。

### 存档校验与开发热更新

固体输送在统一扣料前验证整份转移计划的物品与正整数数量；发现非法项则拒绝本次转换，防止生成无效带载荷或收据。读档对缺失类型、未知物品及非法数量等损坏状态严格拒绝，记录来源、路径和具体原因并保留原数据；不自动删除物品或改写库存 / 入库统计。

编辑运行层代码时先关闭游戏页面，开发服务可保持运行；编译完成后再打开，避免编辑中的中间版本参与模拟和自动保存。开发期间偶发的损坏数据按实际诊断单独处理，不作为长期生产兼容规则。
