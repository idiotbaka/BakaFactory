# 1 TPS 与独立客户端动画

## 逻辑与显示分离

服务器每秒推进一次游戏刻。所有生产、端口冷却和传送带移动均以整数秒结算，最短为 1 tick / 1 秒；配方 duration_ms 必须至少 1000 且整除 1000。

前端动画独立运行在 requestAnimationFrame 上，通常随屏幕刷新率绘制。动画不调用 domain.Step、不推进 tick、不修改输入 / 产物 / 仓库，不提前触发生产完成或 工厂仓库 入库。数量永远显示服务器确认值。

## 共享动画时钟

SimulationAnimationProvider 为工作台提供一个 AnimationClock。所有进度和物品共用一个 RAF，逐帧只更新 progress.value、文本与 transform，不通过 React setState 重绘整张棋盘。

时钟以 factory ID + 已确认 tick 为键。新 tick 到达时开始新的 1 秒显示区间；同一 tick 的再次读取、编辑、缩放或平移不会将时钟归零。使用客户端 performance.now，不依赖客户端 / 服务器墙上时钟一致。

只有存在活跃视觉时才继续请求帧；完成、阻塞、空闲后停止。后台标签页暂停 RAF，回前台立即请求最新快照；不高速补播后台积压帧。

普通模式将持续绘制限制在约 60 FPS，高刷屏不额外重复更新 DOM；节能模式为约 15 FPS，并减弱地图装饰 / 阴影。两者均按 performance.now 的实际时间取样，同样在 1000ms 完成转移，不降低产量、不重置当前 tick 或轨迹。切换模式只调整绘制节奏；快照和交互后允许即时校正一次。偏好保存与系统减少动态效果的默认行为见 [visual-style.md](visual-style.md)。

## 机器进度

服务器在每刻最后，根据物流处理后的库存给出下一显示区间的工作状态。原料已用尽或产物容量不足时，状态为等待 / 满载，不继续预演。

工作时的显示公式：

```text
phase = clamp((客户端当前时间 - 新 tick 快照接收时间) / 1000, 0, 1)
显示进度 = min(配方秒数, 已确认进度 + phase)
```

非工作状态保持已确认进度。小数秒和进度条均可平滑变化，但最多补画下一刻；如果没有后续数据，满一刻后停住，不反复循环制造视觉产物。配方完成、消耗与产物增加仍待下一服务器快照确认。

## 传送带物品

BeltItem 增加稳定 id：机器产物首次进入带时由来源 ID、tick 和目标 ID 生成；在传送带之间或经过端口转移时沿用原 id。同一种矿石每秒进入同一带，也会是不同 id。

ConveyorItemsLayer 是整个网格上的独立绝对定位图层，每个物品按 id 作为 React key，不再把图标绑定在某个格子的 DOM 中。因而物品换格时保留它上一帧的实际绘制位置，不会把下一个相同物品当成上一个图标拉回起点。

当前已确认带格内，物品平滑移向格末端；只有服务器确认转移，轨迹才延伸到下一带。新段从上一段当前绘制位置接上，方向变化时经过目标格中心。阻塞快照到达后在至多 120ms 的视觉校正内停在格末端，不跨过未确认的下一格。

建筑被搬动 / 旋转时，物品跟随建筑重新定位，不飞越地图；断线或后台导致跳过超过两格的快照，直接在新位置恢复格内动画。拆除回收立即移除图标；物流送入机器 / 工厂仓库 则保留图标直到入料动画结束。

## 输入、输出与入库动画

服务器只在物流成功结算后追加 ItemTransfer：唯一事件 id、稳定 payload_id、item、tick，以及来源 / 目标 / 可选途经端口的 ID、类型、坐标和朝向。只记录经过端口的转移和传送带直接进入 工厂仓库；普通带间移动继续由稳定物品 ID 衔接。保留最近 3 tick 的小段历史，随模拟 JSON 保存，无新表或数据库迁移；旧状态缺少 transfers 时归一化为空数组。

- 机器 → OUT / IN → 传送带：图标从机器朝向端口的一侧取出，经过端口中心、目标带中心，接到带末端。图标与带上真实物品使用同一个 key，只有一份。
- 传送带 → OUT / IN → 机器 / 工厂仓库：保留带上同一图标及最后绘制位置，继续经过端口、目标入口并进入目标中心；最后 250ms 缩小、淡出。
- 机器 → 端口 → 机器 / 工厂仓库、传送带 → 端口 → 传送带同样支持。传送带直接进入 工厂仓库 不需要虚构途经端口。

每个已确认转移绘制 1000ms；和带内移动共用同一个 RAF 和绝对定位图层，平移 / 缩放自然跟随棋盘。LogisticsVisualStore 只在快照、动画结束或可见性变化时发布图标列表，帧内只更新 transform / opacity。终点动画结束仅清除视觉残影，不再次扣来源、增加输入或增加仓库；面板数量从快照到达时就显示已确认值。

首次加载不播放存档历史；正常新 tick 只消费上次已确认 tick 之后的新事件，允许轮询偶尔跳过一刻时补接输入动画，最多覆盖 2 tick，相同 tick 的读取 / 编辑不重播。同一 payload_id 不同时绘制入料残影与带上实体。后台立即丢弃未完成转移，恢复后首次读取直接同步；读取间隔超过 2500ms、跳过超过 2 tick、切换工厂或 tick 回退时也直接恢复，不补播旧物流。网络缺帧时允许省略旧动画，物品数仍完全取自服务器。

事件中的来源、端口或目标被移动、旋转、删除时，服务端和客户端均撤销旧路线的视觉记录。堵塞、缺料、目标满载、白名单拒绝不生成事件，因此不会出现假入料。拆除仍沿用即时原子回收，不播放飞向 工厂仓库 的动画。

## 读取频率和边界

前台每次响应后间隔 1000ms 读取，后台 3000ms，单次最多 8 秒且无重叠请求；回前台会立即读取。仍用 factory revision 阻止旧响应覆盖新布局。显示时钟不依赖请求频率，网络延迟可能造成短暂等待；恢复后以服务器状态校正。

当前不是客户端预测整个物流网络，也不是锁步回滚协议。客户端只预测有限的视觉段，省去重复实现产量、容量和物流竞争规则的风险。物品坐标和进度属于显示状态，库存不参与预测。

## 存档兼容

005_one_second_ticks.sql 保留前 4 个迁移内容。旧 tick / 工作进度向下除以 10，时长和冷却向上换算为秒，旧带进度 0～9 转为 0、10 转为 1，并赋予稳定旧物品 id。库存 / 仓库数量完全保留。只转换 tick_rate=10 的记录，重复迁移不会再次换算。

不到一秒的旧工作进度会保守舍去，避免提前发放产物；正常的新存档全部使用整数秒。历史数据升级需要先停止旧 Go 服务，重新启动新版本。

## 代码与验证

- domain/simulation.go：1 秒推进、稳定物品身份、下一区间工作状态、成功转移收据与短历史。
- animationClock.ts：共享帧循环、tick 键、暂停和预测边界。
- animationMath.ts：有界进度与折线轨迹采样，独立可测试。
- SimulationAnimation.tsx：React 订阅、机器和详情进度绘制。
- ConveyorItemsLayer.tsx：物品轨迹、连续移动与位置校正。
- logisticsVisuals.ts：输入 / 输出路线、按物品身份合并图标、完成清理和后台恢复。

测试代码覆盖时钟不重启、共享帧与空闲停帧、预测上限、等待状态、转角采样、1 TPS 配方时长、物品身份与旧存档换算，以及成功转移收据、阻塞 / 拒绝不发事件、事件过期 / 编辑失效、图标去重 / 完成清理、后台恢复与四向路线。按项目约定，测试和服务由用户启动，手动步骤见 [acceptance.md](acceptance.md)。
