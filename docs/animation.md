# 客户端模拟与平滑动画

## 时间来源

工厂计算已迁至浏览器 Worker，1 tick = 1 秒。React 读取本机已完成的模拟状态，共享 RAF 负责显示；网络心跳和云备份不驱动生产或动画。

机器进度仅预演下一刻。传送带物品使用稳定 payload ID，在独立绝对定位图层连续移动。成功物流收据 `transfers` 由本地模拟引擎在统一扣除和接收后生成，保留最近 3 tick；堵塞、目标满和白名单拒绝不生成收据。库存与完成数量只来自本地运行层，视觉不二次结算。

## 绘制与轨迹

`animationClock.ts` 提供所有机器、物品和检视进度共用的 RAF。普通 / 节能模式持续绘制约 60 / 15 FPS，均按真实经过时间采样；无活跃视觉停止 RAF。每帧只更新少量 transform / opacity / progress，不逐帧重绘整张 React 地图。节能模式不改变 1 TPS 或动画时长。

- 同一 tick 的编辑或重复读取不重启动画。
- 带间物品保留同一个节点和上一帧位置，转弯经目标中心。
- 机器 → 端口 → 带、带 → 端口 → 机器 / 仓库、带 → 仓库等使用成功收据延伸路线。
- 收据与带上物品按 payload_id 合并，避免图标重复；入料动画结束只清理视觉，不修改数量。
- 移动、旋转、删除撤销旧路线，回收立即生效，不虚构飞行回收物品。

`logisticsVisuals.ts` 和 `ConveyorItemsLayer.tsx` 保留原有轨迹与去重；输入现在来自本机快照。模型仍为 21×21 / 30px 单元，地图缩放和平移不改变逻辑坐标。

## 暂停与恢复

后台标签页暂停模拟与 RAF；断网或会话失效暂停模拟和 RAF。绘制至多预演已知状态的下一刻，不在没有逻辑 tick 时继续增产。恢复联网需重新校验会话；没有离线收益或积压 tick 重播。

初次载入及云恢复会丢弃旧收据；后台恢复、快照间隔过大或跳过多刻时直接恢复位置，不补播历史物流。恢复云存档会更换本地状态，但云上传确认不替换当前状态。

## 后续离线补算边界

本版不实现补算。纯 `local/simulation.ts` 的 `step` 不含真实时钟和渲染，将来可在 Worker 分批运行最多 14400 tick 等有界任务。应只向 UI 发送进度和最终状态，避免每个补算 tick 都序列化、写盘和重绘；需要允许事件循环处理进度 / 取消并测量不同规模的耗时。不能把当前构建通过当作每 tick 1ms 的性能证明。

相关验证代码包含模拟守恒、环路和竞争、成功收据、连续轨迹、暂停 / 许可到期 / 无追赶；运行状态见 [progress.md](progress.md)，用户步骤见 [acceptance.md](acceptance.md)。
