# 客户端模拟与平滑动画

地下出口载荷与普通地面带使用相同屏幕方向，不按地下类型反转角度：90° 向屏幕下方、270° 向上。端口 SVG 同步此规则；地下段依然无飞行动画，显式配对、稳定载荷 ID 和新到货不可同刻再出料的规则保持。

带上载荷在缩放达到 120% 时显示数量：直接读取当前 payload.count，和图标共享同一 translate3d，zoom 只更新父层反向缩放变量以保持屏幕 12px。数量仅在快照变化时更新，低于门槛及离开传送带后不渲染；不新增 RAF / 逐帧 React 状态，不回写库存。实现与验收见 [物流玩法调整](logistics-upgrade.md)。

建筑 / 物流背景已改为 128px 正视机壳和代码连接线路。BuildingVisual 与放置 / 移动预览共用静态组件；routeGeometry 只在首次遇到类型 / 端口 / 开放边组合时生成并缓存 SVG，方向与阶段由代码叠加，管道亮度 / 机壳液位只消费确认的真实容积。运行状态点与 MachineProgress 保持原实现，ConveyorItemsLayer 不变；机壳、带面与管网不增加 RAF、流动装饰或成功收据，也不回写模拟。实际游戏效果仍需用户验收，资源与连接边缘静态检查见 [building-art.md](building-art.md)。

传送带物品与 GUI 共用 128px 像素 PNG。ConveyorItemsLayer 保留原 payload 节点、key、位置、时序、吸收和成功收据判定，只将内部矿石 / 板材 / 齿轮模板改为 ItemSprite；18px 视觉区域使用像素缩放，黑色轮廓在图片内、阶段光影为静态 CSS。贴图不回写库存，不新增 RAF、逐帧解码或绘制画布；普通 / 节能仍使用同一共享帧时钟。图片缺少映射时保留原 SVG 回退，现行目录与旧档物品均有映射。

手工加工进度移至顶部横栏，仍复用 DetailedProgress / 共享 RAF，仅预演当前批次下一秒，不预演剩余整队列或提前入库。批次编号和剩余数由 Worker 确认；暂停或完整主厂库存的产物上限阻塞时冻结。切厂 / Tab 不创建第二份队列或结算；节能不改变每批工时。

F 的增量 WorldFrame 在主线程先恢复完整确认快照，再交给原有动画层；省略布局 / 安静分厂不省略实际转移收据，也不重播旧事件。观察窗口和终局提示只读确认数据，不创建 transfers、预演或额外 RAF。后台 / 断网暂停和普通 / 节能的时间规则保持不变。

E2e 选中机器人的当前路段为单条静态 SVG 虚线，随确认快照更新，不作移动预演、逐帧路径查询或库存结算。跨区只显示当前 WH 路段 / 确认落点，不跨两幅地图画直线；无路或占格时保留真实机器人位置。查看、定位和筛选不产生新的 transfers 或动画收据，不新增 RAF。

E2d2 蓝图只显示 Worker 确认的预留格与实际施工工时。完成前没有建筑运转、物品飞行或提前产物；第 10 个现场 tick 才原子安装。取消 / 能量中止移除预留标记，设备继续留在机器人 cargo，实际 WH 入库才退款。施工不创建 transfers、不新增 RAF 或装饰循环；暂停 / 刷新不重播安装或退款。

E2b 机器人地图按 Worker 每半秒确认的机器人格位显示静态 SVG；尚未做平滑轨迹，不创建独立 RAF 或预测装卸。过境时隐藏旧厂标记，落地确认后在新厂显示；暂停 / 编辑 / 切厂不重播旧移动。货物由 cargo 和实际端点库存唯一计数，不为机器人生成固体带 transfers 或虚假飞行收据。后续平滑显示需接共享帧时钟且保持这些边界。

物料流体按每 tick 实际容积和上一刻流入 / 流出显示。管道、阀、泵和罐液位使用静态 SVG，不创建逐滴动画或固体 payload 收据；不使用动画结算库存，节能模式不影响流量。

## 时间来源

工厂计算已迁至浏览器 Worker，1 tick = 0.5 秒游戏时间，正常调度默认 2 TPS。React 读取本机已完成的模拟状态，共享 RAF 负责显示；网络心跳和云备份不驱动生产或动画。

开发者倍速时共享时钟与物流图标使用 `stepMs=1000 / TPS`，机器 / 工作室仅预演下一 tick，传送 / 逐格轨迹在对应真实间隔内采样，末端短校正不超过一个 tick。速率改变可重新建立视觉段，重复读取同 tick / 同速率仍不重启动画；库存与事件继续只由 Worker 确认。普通 / 节能约 60 / 15 FPS 上限保持独立，高 TPS 时可能跳过中间视觉帧，不补播历史收据或补算物料。机器最多预演下一刻的 0.5 秒进度；传送带按带定义的 tick 数乘调度间隔计算时长。

机器进度仅预演下一刻。传送带物品使用稳定 payload ID，在独立绝对定位图层连续移动。成功物流收据 `transfers` 由本地模拟引擎在统一扣除和接收后生成，保留最近 3 tick；堵塞、目标满和白名单拒绝不生成收据。库存与完成数量只来自本地运行层，视觉不二次结算。

投料机可在带内行程尚未结束时取走已有载荷，逻辑扣收在该次半秒转换中完成；动画从同一 payload 的上一绘制位置延续到接收目标。飞行动画仍复用一个调度间隔，不占用设备、不延后下一次检测，也不要求源带先走完一格。两次连续取货的动画可自然衔接，不能用动画完成事件设置物流冷却。

## 绘制与轨迹

阶段 C 按 catalog 角色识别所有新旧传送带；手摇带每格 2 tick（1 秒），其他带每格 1 tick（0.5 秒），对当前进度及下一刻进行分段补间。批次只显示一个图形，不用逐件 DOM 扩大绘制负担。整批转移保留 ID；拆批的剩余与新分支各自使用 ID，不能合并绘制造成库存二次结算。物流配置改变取消旧收据路线；暂停 / 缺能冻结带内预演。

`animationClock.ts` 提供所有机器、物品和检视进度共用的 RAF。普通 / 节能模式持续绘制约 60 / 15 FPS，均按真实经过时间采样；无活跃视觉停止 RAF。每帧只更新少量 transform / opacity / progress，不逐帧重绘整张 React 地图。节能模式不改变 2 TPS 或动画时长。

- 同一 tick 的编辑或重复读取不重启动画。
- 带间物品保留同一个节点和上一帧位置，转弯经目标中心。
- 机器 → 端口 → 带、带 → 端口 → 机器 / 仓库、带 → 仓库等使用成功收据延伸路线。
- 收据与带上物品按 payload_id 合并，避免图标重复；入料动画结束只清理视觉，不修改数量。
- 移动、旋转、删除撤销旧路线，回收立即生效，不虚构飞行回收物品。

`logisticsVisuals.ts` 和 `ConveyorItemsLayer.tsx` 保留原有轨迹与去重；输入现在来自本机快照。模型仍为 21×21 / 30px 单元，地图缩放和平移不改变逻辑坐标。

## 暂停与恢复

后台标签页暂停模拟与 RAF；断网或会话失效暂停模拟和 RAF。绘制至多预演已知状态的下一刻，不在没有逻辑 tick 时继续增产。恢复联网需重新校验会话；没有离线收益或积压 tick 重播。

初次载入及云恢复会丢弃旧收据；后台恢复、快照间隔过大或跳过多刻时直接恢复位置，不补播历史物流。恢复云存档会更换本地状态，但云上传确认不替换当前状态。

## 后续离线补算边界

本版不实现补算。纯 `local/simulation.ts` 的 `step` 不含真实时钟和渲染，将来可在 Worker 分批运行最多 14400 tick 等有界任务。应只向 UI 发送进度和最终状态，避免每个补算 tick 都序列化、写盘和重绘；需要允许事件循环处理进度 / 取消并测量不同规模的耗时。不能把当前构建通过当作每 tick 1ms 的性能证明。
