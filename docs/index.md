# BakaFactory 开发文档

本项目依据现有功能和最新需求迭代，不再使用旧 README.md 的阶段路线。

## 当前功能

“诊断”右侧提供“开发者工具”，可开启“仓库下单始终可用”来跳过机械手任务领奖条件。默认关闭并随当前游戏存档保存，不推进阶段或领取奖励；配方 / 设备门槛、起始仓材料与队列规则保持。未正式领奖且有订单依赖该开关时，完成或取消后方可关闭。

首次进入无工厂的命名界面自动播放五页开场漫画“下班计划开启”，配图下方正文每页 3 秒打字显示；完成后保存按账号隔离的本机观看记录，再返回命名表单手动创建。已有工厂不强制弹出，右下角“重放剧情”可重新观看。内容与扩展见 [剧情系统](stories.md)。

领取“是时候解放双手了”后自动播放五页“P1：工厂开饭了”，每页五行定稿正文与开场同角色 / 画风的全新室内配图；复用翻页 / 打字播放器，待播章节随本机记录保存，完成后不再自动弹出。底部重放菜单按已领奖条件开放章节；历史 P2 和云恢复不伪造新领奖通知，可手动重放。

玩法重构 A 至 F 已实现，待用户统一测试与全量游玩。原始 352 物品 / 55 机器 / 329 配方全部导入，另补 P2 启动管道及 P4 手工启动线缆，共 334 条运行配方（含 3 条旧配方），见 [数据审计](gameplay-data-audit.md)。客户端生产、固体 / 流体 / 能源、多厂区、机器人运输 / 作业凭据 / 智能派单 / 施工、地图检视和闭环诊断已接通；静态闭包覆盖能源与真实作业前置，不能据此宣称长局或性能测试通过。

用户名注册 / 登录 / 登出、昵称及单点登录；每人一个浏览器本地世界，初始六个 21×21 厂区，按阶段最多扩为 100 区，各有固定工厂仓库和独立分仓 / 网络；图鉴、方向、连续放置、移动、删除、缩放和平移；Worker 中全部厂区 1 TPS 生产和物流；拆除回收；IndexedDB 原子世界存档；30 分钟自动 / 手动覆盖唯一云备份；换设备恢复及版本冲突选择。

游戏需要联网校验账号，约每 10 秒一次轻量心跳。关闭、后台、休眠或断网时暂停，恢复后继续，不补算暂停时间。旧服务端工厂不导入新架构，账号和数据库原记录保留。

界面采用赛博朋克＋蒸汽波的霓虹工厂画风：像素矢量标题、静态工业落日场景、地图居中的 HUD、建筑快捷键 `1–6`、`F` 沉浸视图、玩家档案和操作指南、可保存的节能模式。普通 / 节能绘制约 60 / 15 帧，生产均为客户端 1 TPS。

全站中英文文字最小 12px，后续开发同样遵守，并由 lint 检查字号下限。工厂工作台整体固定 16:9，宽度约浏览器的 90%、最小 1200px；建造阵列 / 产线现场 / 模组检视固定为 18:58:24 三栏，侧栏独立滚动，窄窗口横向滚动。切换建筑 / 物品不会撑缩工作台或棋盘。地图传送带只显示带面和方向箭头，不显示 BELT 文字。

建造阵列分为建筑 / 物流 / 物品，物品未获得时灰显、曾获得后保持实体色并随存档保存，原顺序保持。顶部仓库摘要已移除，当前分仓库存集中在中央仓库的五列卡片中查看和搜索。

手工加工进度、剩余批数和取消队列统一常驻顶部右侧，工作室不再显示重复的队列卡片；切中央视图也可管理，分厂按现有规则回起始厂取消。工作室可按当前原料一次排入同配方 1～100 批，输入超限自动回填可加工上限；预留原料后逐批按原配方秒数一半、向下取整且至少 1 秒完成，取消只退未完成部分。地图设备仍按原配方工时生产。队列跨厂共享、本机 / 云存档保留，暂停不追赶。

地图机器的手动补料提供批数输入（默认 1）和“从仓库补足原料”，目标包含机器已有原料，仅补缺量；根据每格 100、空余输入格及当前分仓库存计算可容纳的完整批数，超出自动按上限执行，Worker 再次原子复核。不足一批时禁用，不改变生产工时或当前进度。

工作室按六种设备分组，仅设备子分类在中央滚动区域顶部吸顶，无尽垃圾堆随页面滚动，原料 / 产物用图标与数量卡显示。手动分拣台、铁砧锻台和手工工作台默认可用；简易拆解台 / 手摇破碎机 / 手工装配台在首次制造对应设备后永久开放共用手工加工，无需安装。

建筑 / 物流检视提供“获取来源和关联配方”大弹窗，按实际安装道具列出生产来源，明确建筑与道具的名称对应关系，并分开展示该设施可执行的加工配方、加工设备、耗时和阶段前置。

任务标题 / 描述 / 奖励、工作室每批原料 / 产物和仓库中的道具名支持下划线点击，在名称旁展开小型来源卡。卡片展示介绍、代号、物品类型、安装用途及实际产出该道具的配方 / 前置；支持继续点查原料，关闭按钮、外部点击或 Esc 退出。仅查询目录，不改变生产或存档。

中央“工厂”右侧的“任务”提供 P1 九项开放引导任务，按推荐顺序展示，无需接受；达成后手动领取，物品奖励进入起始厂仓库。新增任意厂 WH 真实自动化入库与首次制造流水线机械手任务；制造机械手并领取机制奖励后开放 P2 和仓库下单，旧 P2 以上存档保留解锁。待领奖红点与每条 3 秒的达成气泡不改变模拟。规则见 [任务系统](quests.md)。

仓库下单可递归规划已解锁六类工作室配方，展示整批进位、顺序工序、消耗 / 缺料与最终全部产物。仅起始厂可确认；一次预留材料，使用唯一手工队列逐批自动加工，顶部显示机械手工序；取消回收当前未用原料与已完成物料，刷新 / 云备份保留订单。单次目标最多 1000 个，规划和队列有复杂度上限，详见 [机械手订单](warehouse-orders.md)。

机器人支持九种规格、实际本体部署 / 召回、真实补能、优先级与厂区授权。搬运 / 巡检 / 维护 / 施工走实际路径与工时；跨区经 WH 和 8 秒行程，取消携货实际返仓；训练原子消费匹配凭据。诊断页显示本区缺口、能源 / 物流等待、物品依赖 / 名义产能及世界最近 60 个运行 tick 的实际制造与逐格流量。首次制造智能机器人达成六阶段主目标，制造可扩展智能工厂许可证达成后续沙盒目标。增量快照重用未变布局、空厂只更新时钟，仍保存完整世界；提供独立纯模拟测量入口，尚未实测性能。多格批量蓝图、离线收益、多人交易及多实例服务不在本轮范围。

## 本地启动

要求本机 Node.js 22.13+ 或 24+、npm、Go 1.26+。SQLite 由纯 Go 驱动提供，无需 Docker、C 编译器或数据库进程。

```bash
# 第一次安装依赖
npm run setup
# 一键启动 Go 后端与 Vite 前端
npm run dev
```

打开 <http://127.0.0.1:5173>。后端健康检查为 <http://127.0.0.1:8080/health>。前端支持热更新；Go 修改需 Ctrl+C 后重启该命令。启动自动执行尚未应用的 migration，001～005 保持原样；006 增加独立云存档和单会话约束。新游戏不读取旧布局 / 模拟 / 仓库。请勿删除数据库。

服务器账号及云备份默认在 apps/server/data/bakafactory.local.db；游戏主存档在浏览器 IndexedDB，按账号隔离。Go 读取进程环境变量，不自动加载 .env，变量样例见 apps/server/.env.example。

## 用户执行的检查命令

| 命令                                                                                               | 用途                                                         |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `npm run lint`                                                                                     | ESLint、TypeScript、Go 格式和 go vet                         |
| `npm test`                                                                                         | 前后端单元 / 集成测试，使用临时数据                          |
| `npm run build`                                                                                    | 构建 Web 和 Go 可执行程序                                    |
| `npm run test:smoke`                                                                               | 构建后启动临时服务，检查单点登录、云备份及重启保存           |
| `npm run check`                                                                                    | 上述所有步骤                                                 |
| `npm run generate:api`                                                                             | 依据 OpenAPI 更新 API 类型                                   |
| `npm run import:gameplay`                                                                          | 从原案 JSON 生成目录并进行静态材料 / 能源 / 真实作业闭包审计 |
| `npm run benchmark:build`                                                                          | 编译纯模拟测量入口，不运行测量                               |
| `npm run benchmark -- --districts 6 --machines 24 --robots 12 --ticks 60 --seed 1 --profile mixed` | 用户运行隔离的合成测量，不访问存档 / 数据库                  |
| `npm run migrate`                                                                                  | 手动执行待应用迁移                                           |

本轮服务启动和测试由用户完成。`npm run dev` 是本机浏览器验收入口；`npm start` 用于构建后的生产服务，使用 Secure Cookie，账号功能需要 HTTPS。
