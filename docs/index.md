# BakaFactory 开发文档

本项目依据现有功能和最新需求迭代，不再使用旧 README.md 的阶段路线。

## 当前功能

P2 新增“舱门过于拥挤”材料提交关键任务，实际提交基础铁板 / 铜条各 50 后领奖，解锁各厂独立的取货 / 存入终端升级与五页漫画。终端可移动、不可删除；取货支持 1～2 固体轮询并跳过缺货，存入四面接货至唯一总仓库。P2/P3/P4 起累计上限为 2/1、4/2、6/3。费用、兼容与验收见 [仓库 IO](warehouse-io.md)。

本机 / 云存档校验失败时，控制台打印来源、字段路径和具体原因；带载荷会细分物品、标识、数量与进度，并提供必要的局部诊断。非法数据拒绝读取并保留原档，不自动删除物品或调整库存 / 任务统计。定位步骤见 [读档诊断](acceptance.md#存档读取失败的控制台诊断待用户执行)。

固体物流会依次尝试上游候选物品：投料机遇到某种物品满格或不被下游接收时，可改送后续可运输物品。OUT / IN、各级投料机和固体分流器共用修正；不能腾空的满带路线会释放预留并允许改试其他分支，保持批次、间隔和守恒。范围与约束见 [候选物品与阻塞](simulation.md#固体物流的候选物品与阻塞)，回归代码和手动场景待用户执行。

初阶自动投料机 R1039 每批材料减为机械抓取爪 1、低速传动轴 1、分拣料箱 1，产出与工时保持；按开发期规则直接应用新配方，详见 [玩法适配](gameplay-plan.md)。

“开发者工具 → 功能测试”支持模拟倍速：输入 1～60 的整数 TPS 并应用，默认 1，可一键恢复。只调整 Worker 调度间隔，每 tick 仍执行原一秒游戏逻辑，顶部读数和动画同步；当前页面临时生效，刷新、换账号或关闭工具后恢复 1 TPS，不写入存档。后台 / 断网 / 许可失效仍暂停且不补算，实际高倍速取决于设备负载。边界见 [模拟规则](simulation.md#开发者模拟倍速)。

任务页“待完成”列表优先显示“已达成 · 待领奖”，再显示“进行中”，同一状态内保留原推荐顺序；已完成列表保持原顺序，领奖和阶段开放规则不变。

建造阵列、工作室、仓库、诊断物品和机器人列表支持名称 / 编号、拼音全拼与首字母的连续部分搜索，例如“废铜线”可用 feitongxian、ftx、tongx 查找。开发工具从目录自动生成小索引，新增物品随导入 / 构建更新，浏览器不加载完整拼音词库；方案与维护见 [拼音搜索](search.md)。

生产静态资源按类型设置浏览器缓存：Vite 内容哈希资源与版本化字体缓存一年，入口和未版本化文件每次校验；账号 / 心跳 / 云存档与静态错误仍为 no-store。Go 负责策略，nginx 透传；部署、更新和验收见 [静态资源缓存](static-assets.md)。

36 台复杂配方候选机器（审查表 35 台生产机器与 M21 液压动力站）现在可在连续建造时按 E 或点当前卡片右上角按钮切换 1×1 / 2×2，默认 1×1。卡片标注“多尺寸”，检视列出支持及当前尺寸；点击格为左上角，旋转 / 移动保留占地。物流、能源、机器人、蓝图预留及本机 / 云存档已接入完整占格，旧档保持单格。设计、边界与验收见 [多格机器](machine-footprints.md)，自动测试和实际游戏效果待用户验证。

地图放大至 120% 起，建筑类机器在格子下半部显示三字以内的中文简称，白字配工厂地面色描边；独立文字层保持 12px，不随地图放大字号。物流、传动轴 / 线缆 / 电池等非机器不显示；放置 / 移动预览同步，完整名称仍在提示与检视。全部简称及边界见 [机器地图简称](machine-map-names.md)。

全站（含登录 / 注册）已接入项目内分发的 Fusion Pixel Font 12px 比例简中 Regular，保留 OFL 与上游许可证；小字号不粗体、全局不斜体。登录进入工厂时使用真实文件完成数的进度条，先完成字体 / 全部物品与建筑图标预热，再启动存档 / 在线校验和工厂运行层；失败可重试已保留进度。来源、缓存边界和检查见 [字体与资源预热](fonts-and-loading.md)。

现行 352 种物品及 3 种旧档物品已接入 128×128 透明像素贴图，保留约 32 格的 MD / SFC 像素结构与黑色轮廓；图鉴、配方、仓库、任务、来源查询和传送带成功转移共用资源。阶段色显示为静态脚下光影，详情与重建方式见 [物品贴图](item-art.md)。

全部 92 个建筑 / 物流定义已接入正式像素外观：80 张 128px 透明正视机壳，12 个可拼接物流定义使用缓存整数 SVG 几何；图鉴 / GUI 使用阶段脚下光影，地图 / 放置预览使用建筑阶段描边与独立代码方向箭头。图片不随方向旋转；机器状态点、进度和物品移动复用原实现。来源、全量预览和复现见 [建筑与物流贴图](building-art.md)，实际游戏显示待用户验收。

开发者工具默认隐藏。登录并完成本机存档加载后，F12 控制台执行 `bakaFactory.devTools(true)` 开启、`bakaFactory.devTools(false)` 关闭、`bakaFactory.devTools()` 查看状态；显示偏好按账号保存在当前浏览器 IndexedDB，刷新保留，不进入云备份。关闭时返回工厂视图，不改其中已启用的功能测试设置。

初始六厂区中，起始厂使用玩家填写的名称，其余默认“未命名工厂 2”至“未命名工厂 6”，可在厂区管理中更名；已有存档名称保持。

任务页移除通用规则长说明，工作室拾荒提示精简；六阶段目标采用简短搞怪叙事，终局任务卡保留实际解锁条件。能源页常显 P1 手工 / P2 机械 / P3 液压 / P4 电力，未解锁项灰显禁用；P1 显示 BAKA-01 的趣味手工动力自评，不计入真实能源。

中央不再单列“诊断”；开发者工具内提供“功能测试 / 闭环诊断”子页，原仓库下单开关位于功能测试，诊断保留观察数据和设备定位。机器人页按准备、部署、机队和任务控制分区，P2 以发条车 / 初级搬运站 / 本厂短途搬运为引导，进阶功能按阶段 / 机型折叠。能源页按机械 / 液压 / 电力分开显示搭建流程、供需与网络状态，炉体燃料单列，储能规则只在电力系统中展开查看。

图鉴搜索框在面板内收缩，下方提供 P1～P6 阶段筛选；建筑 / 物流只允许已解锁阶段，物品可预览未来阶段，同阶段保持目录原序。地图标题右侧可用下拉框快捷切厂。任意厂区均可拾荒、工作室加工、机械手下单和取消，全世界始终共用总仓库与主厂唯一队列；切厂不新增加工队列。仓库卡片统一预留顶部下单区，图标 / 名称对齐；机器 / 物流检视的来源按钮下方，在已有下单权限且实际安装道具可由工作室制作时提供“机械手下单”，复用现有订单计划和校验。

地图传送带按邻格指向本格的箭头补接弯头 / 多入口交汇口，代码绘制像素金属轨道、带面、横纹和独立方向箭头；开放端贴合格边、空闲端封闭。放置 / 移动预览同步，不改变真实物流或物品动画。

地图流体管道沿用邻格朝向判定，代码绘制直线 / 方形弯头 / 汇流口、管箍和出口箭头，确认有液时提高内腔亮度；预览同步。轴网、电缆和液压动力线各有独立几何与配色。此为静态视觉连接，不改变流体 / 能量输送判定、流量、库存或存档。

“开发者工具 → 功能测试”可开启“仓库下单始终可用”来跳过机械手任务领奖条件。默认关闭并随当前游戏存档保存，不推进阶段或领取奖励；配方 / 设备门槛、总仓库材料与队列规则保持。未正式领奖且有订单依赖该开关时，完成或取消后方可关闭。

首次进入无工厂的命名界面自动播放五页开场漫画“下班计划开启”，配图下方正文每页 3 秒打字显示；完成后保存按账号隔离的本机观看记录，再返回命名表单手动创建。已有工厂不强制弹出，右下角“重放剧情”可重新观看。内容与扩展见 [剧情系统](stories.md)。

领取“是时候解放双手了”后自动播放五页“P1：工厂开饭了”，每页五行定稿正文与开场同角色 / 画风的全新室内配图；复用翻页 / 打字播放器，待播章节随本机记录保存，完成后不再自动弹出。底部重放菜单按已领奖条件开放章节；历史 P2 和云恢复不伪造新领奖通知，可手动重放。

玩法重构 A 至 F 已实现，待用户统一测试与全量游玩。原始 352 物品 / 55 机器 / 329 配方全部导入，另补 P2 启动管道及 P4 手工启动线缆，共 334 条运行配方（含 3 条旧配方），见 [数据审计](gameplay-data-audit.md)。客户端生产、固体 / 流体 / 能源、多厂区、机器人运输 / 作业凭据 / 智能派单 / 施工、地图检视和闭环诊断已接通；静态闭包覆盖能源与真实作业前置，不能据此宣称长局或性能测试通过。

用户名注册 / 登录 / 登出、昵称及单点登录；每人一个浏览器本地世界，初始六个 21×21 厂区，按阶段最多扩为 100 区，各有固定 WH、共用总仓库与独立网络；图鉴、方向、连续放置、移动、删除、缩放和平移；Worker 中全部厂区 1 TPS 生产和物流；拆除回收；IndexedDB 原子世界存档；30 分钟自动 / 手动覆盖唯一云备份；换设备恢复及版本冲突选择。

游戏需要联网校验账号，约每 10 秒一次轻量心跳。关闭、后台、休眠或断网时暂停，恢复后继续，不补算暂停时间。旧服务端工厂不导入新架构，账号和数据库原记录保留。

界面采用赛博朋克＋蒸汽波的霓虹工厂画风：像素矢量标题、静态工业落日场景、地图居中的 HUD、建筑快捷键 `1–6`、`F` 沉浸视图、玩家档案和操作指南、可保存的节能模式。普通 / 节能绘制约 60 / 15 帧，生产均为客户端 1 TPS。

全站中英文文字最小 12px，后续开发同样遵守，并由 lint 检查字号下限。工厂工作台整体固定 16:9，宽度约浏览器的 90%、最小 1200px；建造阵列 / 产线现场 / 模组检视固定为 18:58:24 三栏，侧栏独立滚动，窄窗口横向滚动。切换建筑 / 物品不会撑缩工作台或棋盘。地图传送带只显示带面和方向箭头，不显示 BELT 文字。

建造阵列分为建筑 / 物流 / 物品，物品未获得时灰显并显示“尚未获得”，曾获得后保持实体色并显示“库存 数量”，耗尽显示“库存 0”；获得记录随存档保存，原顺序保持。物品卡片与建筑 / 物流卡片均读取共用总仓库数量，切厂保持一致。顶部仓库摘要已移除，完整总仓库仍可在中央仓库的五列卡片中查看和搜索。

手工加工进度、剩余批数和取消队列统一常驻顶部右侧，工作室不再显示重复的队列卡片；切中央视图也可管理，分厂也可取消同一队列。工作室可按当前原料一次排入同配方 1～100 批，输入超限自动回填可加工上限；预留原料后逐批按原配方秒数一半、向下取整且至少 1 秒完成，取消只退未完成部分。地图设备仍按原配方工时生产。队列跨厂共享、本机 / 云存档保留，暂停不追赶。

地图机器的手动补料提供批数输入（默认 1）和“从仓库补足原料”，目标包含机器已有原料，仅补缺量；根据每格 100、空余输入格及总仓库存计算可容纳的完整批数，超出自动按上限执行，Worker 再次原子复核。不足一批时禁用，不改变生产工时或当前进度。

工作室按六种设备分组，仅设备子分类在中央滚动区域顶部吸顶，无尽垃圾堆随页面滚动，原料 / 产物用图标与数量卡显示。手动分拣台、铁砧锻台和手工工作台默认可用；简易拆解台 / 手摇破碎机 / 手工装配台在首次制造对应设备后永久开放共用手工加工，无需安装。

建筑 / 物流检视提供“获取来源和关联配方”大弹窗，按实际安装道具列出生产来源，明确建筑与道具的名称对应关系，并分开展示该设施可执行的加工配方、加工设备、耗时和阶段前置。

任务标题 / 描述 / 奖励、工作室每批原料 / 产物和仓库中的道具名支持下划线点击，在名称旁展开小型来源卡。卡片展示介绍、代号、物品类型、安装用途及实际产出该道具的配方 / 前置；支持继续点查原料，关闭按钮、外部点击或 Esc 退出。仅查询目录，不改变生产或存档。

中央“工厂”右侧的“任务”提供 P1 九项、P2 二十项及 P3～P5 三项终局，共 32 项。P2 包含九项逐物品百件自动化入库、轴功加工 / 蒸汽储罐 / 发条车运输 / 十区扩建，以及五项首造设备 / 物流补给任务；进度与物流 / 配方材料奖励按项显示。P1～P5 仅在完成并领取阶段终局奖励后推进；终局需先完成本阶段普通任务至少一半（向上取整，达成未领奖也计数），P1 为 4/8，P2 为 10/19。隐藏项不计待完成数量 / 红点，开放后以粉色描边与标签突出，卡片明确下一阶段；P1 终局同时开放仓库下单。旧档保留已有阶段，新 P2 事件从更新后累计，不按库存补造历史；首造 / 厂区数可由真实已有记录补认，奖励需手动领取。待领奖红点和每条 3 秒气泡保留。规则见 [任务系统](quests.md)。

仓库下单可递归规划已解锁六类工作室配方，展示整批进位、顺序工序、消耗 / 缺料与最终全部产物。任意厂区可确认；一次预留材料，使用唯一手工队列逐批自动加工，顶部显示机械手工序；取消回收当前未用原料与已完成物料，刷新 / 云备份保留订单。单次目标最多 1000 个，规划和队列有复杂度上限，详见 [机械手订单](warehouse-orders.md)。

机器人支持九种规格、实际本体部署 / 召回、真实补能、优先级与厂区授权。搬运 / 巡检 / 维护 / 施工走实际路径与工时；跨区经 WH 和 8 秒行程，取消携货实际返仓；训练原子消费匹配凭据。诊断页显示本区缺口、能源 / 物流等待、物品依赖 / 名义产能及世界最近 60 个运行 tick 的实际制造与逐格流量。首次制造智能机器人达成六阶段主目标，制造可扩展智能工厂许可证达成后续沙盒目标。增量快照重用未变布局、空厂只更新时钟，仍保存完整世界；提供独立纯模拟测量入口，尚未实测性能。多格批量蓝图、离线收益、多人交易及多实例服务不在本轮范围。

## 本地启动

要求本机 Node.js 22.13+ 或 24+、npm、Go 1.26+。SQLite 由纯 Go 驱动提供，无需 Docker、C 编译器或数据库进程。

### 新开发环境准备

先在终端确认工具可用；Node.js 版本还应满足根目录 package.json 的 engines，Go 最低版本以 apps/server/go.mod 为准。

```bash
node --version
npm --version
go version
```

macOS 已安装 Homebrew 时，可安装缺少的工具（已有符合要求的版本无需重装）：

```bash
brew install node@22 go
```

Homebrew 的 node@22 为独立版本；若终端找不到 node / npm，将下面一行加入所用 shell 的配置文件（zsh 为 ~/.zprofile），然后重新打开终端：

```bash
export PATH="$(brew --prefix node@22)/bin:$PATH"
```

其他系统可安装对应平台的 Node.js 和 [Go 官方发行版](https://go.dev/doc/install)，确保 node、npm 和 go 位于 PATH。项目不要求全局安装 Vite 或 TypeScript。

### 安装依赖与启动

在仓库根目录执行：

```bash
# 第一次安装依赖
npm run setup
# 一键启动 Go 后端与 Vite 前端
npm run dev
```

打开 <http://127.0.0.1:5173>。后端健康检查为 <http://127.0.0.1:8080/health>。前端支持热更新；Go 修改需 Ctrl+C 后重启该命令。启动自动执行尚未应用的 migration，001～005 保持原样；006 增加独立云存档和单会话约束。新游戏不读取旧布局 / 模拟 / 仓库。请勿删除数据库。

setup 通过 npm ci 按 package-lock.json 重建 npm workspace 依赖，再下载 Go 模块，不改写锁文件；需要能够访问 npm registry、Go 模块代理和校验服务。新增 / 升级 npm 依赖时仍使用 npm install 并提交对应锁文件。dev 会先编译 Go 后端到 .runtime，再同时启动 API 与 Vite；首次编译可能较慢，等待终端出现 Vite 地址。Ctrl+C 停止两端。若提示 go 不存在，检查 PATH；若提示缺少 vite 等模块，重新运行 setup；端口被占用时先停止自己此前启动的服务，Vite 不会自动换端口。不要使用 npm start 代替本地开发入口。

若 Go 模块下载因网络超时失败，可按所在网络选择可访问的模块代理。例如使用 [Goproxy.cn](https://goproxy.cn/)：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
npm run setup
```

该设置仅保存到当前用户的 Go 工具配置，不写入项目；保留默认校验数据库和 go.sum 校验。恢复默认代理使用 `go env -u GOPROXY`，不要通过关闭校验解决网络故障。

服务器账号及云备份默认在 apps/server/data/bakafactory.local.db；游戏主存档在浏览器 IndexedDB，按账号隔离。Go 读取进程环境变量，不自动加载 .env，变量样例见 apps/server/.env.example。

## 用户执行的检查命令

| 命令                                                                                               | 用途                                                         |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `npm run lint`                                                                                     | ESLint、TypeScript、Go 格式和 go vet                         |
| `npm test`                                                                                         | 前后端单元 / 集成测试，使用临时数据                          |
| `npm run build`                                                                                    | 构建 Web 和 Go 可执行程序                                    |
| `npm run test:smoke`                                                                               | 构建后启动临时服务，检查单点登录、云备份及重启保存           |
| `npm run check`                                                                                    | 上述所有步骤                                                 |
| `npm run generate:api`                                                                             | 依据 OpenAPI 更新 API 类型                                   |
| `npm run generate:search`                                                                          | 从当前目录自动生成名称全拼 / 首字母索引                      |
| `npm run import:gameplay`                                                                          | 从原案 JSON 生成目录并进行静态材料 / 能源 / 真实作业闭包审计 |
| `npm run benchmark:build`                                                                          | 编译纯模拟测量入口，不运行测量                               |
| `npm run benchmark -- --districts 6 --machines 24 --robots 12 --ticks 60 --seed 1 --profile mixed` | 用户运行隔离的合成测量，不访问存档 / 数据库                  |
| `npm run migrate`                                                                                  | 手动执行待应用迁移                                           |

默认由用户启动服务和执行测试；实际执行状态见 [progress.md](progress.md)。`npm run dev` 是本机浏览器验收入口；`npm start` 用于构建后的生产服务，使用 Secure Cookie，账号功能需要 HTTPS。
