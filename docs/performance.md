# 性能入口与实际边界

F3 已实现增量快照、空厂时钟路径、单份行业进度克隆、厂 / 端点与派单预留索引，以及自动保存背压合并。这里提供测量方法，不包含已经执行的性能数字。服务、自动测试、浏览器和测量均由用户运行。

## 纯模拟测量

先编译，再显式运行。没有服务、账号、数据库、IndexedDB、真实存档或上传；使用内存中的合成已付库存 / 能量。不能把测量数据导入正式存档。

```bash
npm run benchmark:build
# 小规模
npm run benchmark -- --districts 6 --machines 12 --robots 12 --ticks 60 --warmup 5 --seed 1 --profile mixed
# 100 个空厂：对比安静厂区的时钟 / 快照成本
npm run benchmark -- --districts 100 --machines 0 --robots 0 --ticks 60 --warmup 5 --seed 1 --profile idle
# 8,000 机器 + 500 机器人：参数上限内的合成混合负载
npm run benchmark -- --districts 100 --machines 80 --robots 500 --ticks 60 --warmup 5 --seed 1 --profile mixed
```

基础时钟为 2 TPS，`--ticks 120` 对应 60 秒游戏时间；计时结果仍是每个半秒转换的实际耗时，不是每秒合计。

参数边界：厂 1～100；每厂生产机器 0～80；全局机器人 0～500、每厂最多 40；计时 tick 1～600，预热 0～60；seed 为 1～2147483647 的整数。profile 为 idle / production / mixed：idle 只有 WH；production 放置零工艺功率的 M03；mixed 另含热能 M05、真实规则的站点 / 机器人取送。只有 mixed 部署 robots，输出 actual 字段说明实际数量和机器人状态，不能只引用请求参数。

固定种子生成确定性标识与布局；机器缓存 / 热燃料在计时外补足并腾空，用来维持可重复负载，不代表正常玩家产量。机器人仍受 WH 面速、通路、占格和真实剩余能量限制，可能进入等待；并非持续满速行走基准。当前合成案例没有覆盖所有管网 / 电网拓扑或所有配方，不能据此推导任意工厂的最坏时间。

JSON 输出包含 tick 毫秒、增量生成 + structuredClone 毫秒、完整世界 structuredClone 毫秒的 mean / p50 / p95 / max；增量 / 完整 JSON 字节量用于可重复对比，不等同于浏览器结构化克隆的传输字节。统计不包含建造夹具、补料、JSON 编码、浏览器 Worker 排队、DOM、RAF、存储和网络时间。记录 Node 版本、CPU / 内存、参数与输出后比较，不跨设备直接承诺同一耗时。

## 浏览器全局验收

在完整游玩后的真实存档上观察，不要伪造库存。普通 / 节能、前后台、满仓 / 缺能、跨区和多机器人分别观察：逻辑是否保持 2 TPS、是否跳过休眠追赶、输入响应、画面帧时间、主线程 / Worker 的长任务、内存与保存耗时。不要用测量脚本给出的模拟 tick 时间代替浏览器 FPS。

客户端只渲染当前厂地图，普通 / 节能共享 RAF 约 60 / 15 FPS。活跃厂每刻仍传递其变化模拟状态，所有厂仍以 2 TPS 运行；持续制造的百厂不会得到空厂同样的开销。主线程保存完整世界，每 5 秒游戏时间（10 tick） 尝试自动保存，慢写入只合并最新待保存意图；编辑 / 手动保存与关闭仍排队保证完整性。大库存、密集流体、BFS 拥堵和硬盘写入仍可能成为瓶颈。

## 验证记录

本轮仅编译了测量入口、通过静态检查和前后端编译，没有运行测量或浏览器测试。所有规模的耗时、FPS、内存与长时间稳定性仍待用户验收；不引用原案未经验证的亚秒离线补算目标。游戏继续不计算离线收益。
