# 2 TPS 与传送带

## 设计与范围

基础模拟为 2 TPS，每 tick 代表 0.5 秒游戏时间。所有厂区仍由一个 Worker 串行原子推进，每次成功转换 revision 加一。没有传送带专用定时器，也不通过动画结算物品；本轮建立可供生产、投料和其他设备继续使用的共享时间步长。

| 传送带         | 阶段 | 每格时间        | 每格载荷 | 额定供能  |
| -------------- | ---- | --------------- | -------- | --------- |
| 手摇传送带     | P1   | 1 秒 / 2 tick   | 2 件     | 无        |
| 机械传送带     | P2   | 0.5 秒 / 1 tick | 2 件     | 轴功 1 kW |
| 液压输送带     | P3   | 0.5 秒 / 1 tick | 10 件    | 液压 2 kW |
| 电动传送带     | P4   | 0.5 秒 / 1 tick | 20 件    | 电力 2 kW |
| 高速精密传送带 | P5   | 0.5 秒 / 1 tick | 50 件    | 电力 3 kW |
| 柔性立体输送带 | P6   | 0.5 秒 / 1 tick | 100 件   | 电力 4 kW |

参数通过 `scripts/import-gameplay.mjs` 生成到 `apps/server/internal/catalog/definitions.json`，不修改 v0.9 原案；网页版地下端口现用简易齿轮 2、基础铁板 2。地下出口仍为独立的 6 件缓存、无需动力；其原有 `belt_ticks=1` 现在代表 0.5 秒，地下段继续瞬时路由。

## 时间与数量的单位

`apps/web/src/game/local/simulationTime.ts` 是运行层的时间入口：基础 TPS、每刻秒数 / 毫秒数、秒与 tick 换算、指定秒间隔和整单位速率预算集中定义。新增设备不要再用一次调用等于一秒的假设。

| 数据                                                         | 单位 / 推进方式                                                     |
| ------------------------------------------------------------ | ------------------------------------------------------------------- |
| `simulation.tick`、收据 / 异常 / 派单时间戳                  | 非负整数基础 tick，每秒两次                                         |
| 机器 `progress` / `duration` / `cooldown`、工作室 `progress` | 秒，每刻增加 / 减少 0.5；保存为精确半秒值                           |
| 配方 `duration_ms`                                           | 毫秒，至少 500，500 的整数倍；现有配方工时不变                      |
| `belt.progress` / `belt_ticks`                               | 整数基础 tick；界面换算为秒                                         |
| 投料 `configuration.interval`                                | 秒，0.5～60、0.5 的整数倍；自动投料机默认 0.5 秒，其他端口默认 1 秒 |
| 机器和网络功率                                               | kW，保持原额定值                                                    |
| 燃料余热 / 工作能量 / 站储能 / 电池电量                      | kJ，0.5 的整数倍                                                    |
| 仓库、输入 / 产物、流体、载荷数量                            | 整单位，不允许半件物品或半单位流体                                  |

自动投料机默认 0.5 秒 / 批、每批最多 20；已显式保存的间隔保留，其他端口规格保持。Worker 编辑、客户端读档和 Go 云备份均校验同一精度。后续调整投料默认值或配方时长只需按这些单位配置，不需要新定时器。若将来再次提高基础 TPS，还需同步协议和两端精度校验；开发者倍速不能替代更细的时间步长。

投料机设置 0.5 秒时每刻检查后方已有载荷并完成一次可行扣收，不等待来源带的整格行程，也不附加一段传输工时。带内取货优先于自行出料，设备之间的来源竞争与真实容量阻塞分开诊断；完整时序见 [模拟规则](simulation.md#投料机取带时序与状态)。

## 各系统的实际时序

- 机器和唯一工作室队列每刻推进 0.5 秒。例如原 10 秒地图配方仍需 20 tick，手工 5 秒仍需 10 tick；输入仍在完成时扣除，取消仍只退真实未用材料。
- 供能网络每刻重建。发电、驱动、工作和电池充放预算均为 `kW × 0.5 秒`；记录 / HUD 再换回 kW。例如机械带每刻消耗 0.5 kJ，加上轴网自身损耗，不能以翻倍 TPS 免费加速供能。生产积累够半秒额定工作能量才推进半秒，缺能不满速。
- 0.5 kJ 是二进制可精确表示的值，不引入任意小数或宽泛容错。电池保持 88% 效率、百分之一 kJ 余数及原充放上限，不互充、不在同刻充放。机器人实体电量仍为整数 kJ；补能站以交替整单位预算保留奇数速率，例如 15 kW 为每半秒 7 / 8 kJ，不能每刻向下取整丢掉速率。
- 固体物流每刻规划一次，冷却以秒递减。WH 自动输出每面、取货终端仍最多每秒一件，不能因多一次调度翻倍；终端被投料机提取同样遵守冷却。接收整批只允许目标旧载荷完全腾空；100 件向 2 件慢带拆分仍保留剩余和唯一载荷 ID。满闭环可同时移动，新到物品不在同刻再次移动。竞争顺序按游戏秒轮换，分流按自身动作间隔轮换，避免基础 tick 翻倍后只在偶数刻就绪的来源固定偏向同一设备。
- 物料管道每半秒转移一格，原 fluid_rate 数值按每次动作计，理论每秒流量翻倍；统计按每个真实动作计数。泵每半秒消费真实 2.5 kJ，额定功率保持 5 kW，缺能停止。WH 流体输出每面仍最多每秒 1 u。
- 机器人补能每刻分配已付站储能；每半秒走一格、每格 1 kJ，装卸 / 作业 / 跨厂过境仍按秒级动作推进。历史 `action_ticks`、`remaining_ticks`、`work_progress` 字段沿用秒级行动单位，不新增移动相位字段。自主评估和异常成熟仍为 5 秒，基础时间戳为 10 tick 的差值。
- 所有厂区使用同一半秒时钟，总仓库和唯一行业 / 手工队列仍只结算一次。诊断保留 60 秒 / 120 tick，分钟速率按游戏秒换算；自动本机保存保持每 5 秒游戏时间 / 10 tick。

## 调度、动画与开发者工具

Worker 默认每 500ms 执行一刻。开发者工具支持 2～60 的整数调度 TPS，默认 / 恢复值为 2；每刻游戏时间始终为 0.5 秒，所以 4 TPS 是二倍速、60 TPS 是目标三十倍速。测试速率只在当前页面生效，不写入存档。

在线许可、心跳和云备份仍按真实时间。暂停、后台、休眠、断网不追刻、不结算离线收益；切速率只替换单一定时器。实际高倍速受设备负载限制。

共享 RAF 仍为普通约 60 / 节能约 15 FPS。机器最多预演下一刻的 0.5 秒进度；物品按带定义的 tick 数和实际调度间隔补间，100 件仍只画一个载荷图形。成功收据保留最近 3 tick 并按 payload ID 合并；首次读取和后台恢复不补播。地图 120% 起复用载荷节点显示真实数量，固定屏幕 12px；低于门槛和吸收尾迹不显示，不增加帧时钟。固定工作台、编辑手势和字体下限保持。

## 基本读档兼容

保持 `format_version=1`、`rules_version=3`，以 `simulation.tick_rate` 区分旧 1 TPS / 新 2 TPS。读取旧档时仅在克隆中执行一次时钟升级：

1. 所有厂区 tick、异常 / 服务 / 作业凭据 / 自主派单 / 日志的基础时间戳乘二，设置 `tick_rate=2`。
2. 带内进度按旧 / 新格内时长换算，向下取整至合法基础 tick；载荷 ID、数量不变。
3. 生产 / 手工进度、冷却和机器人秒级行动工时保持；仓库、燃料、输入 / 产物、管内容积、机器人实体 / 携货和已有任务不重新结算。瞬时视觉收据清空。
4. 进入当前严格校验；后续读取 2 TPS 不再次转换。Go 同时接受合法旧 / 新备份，手摇带旧进度范围保留最小兼容。

不新增数据库迁移，不删除账号 / 工厂 / 数据库，不增加多套旧玩法运行分支。旧带进行中的格内剩余时间允许按新规则缩短；不保证在相同墙钟时刻复现旧系统的物流相位。

## 用户验收

本轮未启动服务、未运行自动 / 浏览器 / HTTP 冒烟测试；实际执行状态见 [进度](progress.md)。

1. 用户运行 `npm test`，再运行 `npm run dev`。旧档正常打开，HUD 默认为 2 TPS；刷新 / 切厂 / 本机保存 / 手动云备份和恢复后，库存、队列、设备 ID 保持，tick 不重复乘二。
2. 分别搭建带 → 箱 / WH，准备表中满批真实货物及对应能源；检查手摇每格 1 秒、其余每格 0.5 秒。缺能 / 禁用 / 下游满时不丢货；恢复后继续，不补算暂停时间。
3. 用柔性带 100 件接手摇带，检查每次最多 2 件、总量始终 100。验证整批满闭环、连续拐弯、分流、UG 接入、移动和拆除，回收只返真实现存物品。
4. 箱 → 投料机 → 箱，把间隔设为 0.5 / 1 / 1.5 秒，在来源充足且及时腾空目标时，3 秒分别最多 6 / 3 / 2 次成功动作，每批最多 20 件；确认过滤 / 堵塞时不扣库存。WH 各输出面和取货终端连续 3 秒最多各 3 件。
5. 同时观察地图原 10 秒配方、手工 5 秒配方和真实燃料出功：分别仍为 10 / 5 秒；1 kW 每秒 1 kJ，电池每秒充放不超 100 kW，充入保持 88%。低供能生产不能满速。
6. 验证流体每半秒逐格转移、不混液；泵每半秒支付 2.5 kJ、断能停止。机器人每半秒一格、跨厂行程和作业工时保持，补能站奇数 kW 速率不缩水，停靠不产生真实作业凭据。
7. 开发工具设 4 TPS 后相同游戏工作用约一半真实时间；恢复 2 TPS、关闭工具、刷新均回正常速度。后台 / 断网暂停，无追赶。普通 / 节能下动画连续且不改变产量，工作台尺寸不跳变。

回归入口包括 `simulationTime.test.ts`、`worker.test.ts`、既有生产 / 物流 / 能源 / 流体 / 机器人场景及 Go `simulation_time_test.go`。测试中的 `testTime.ts` 只为原有“秒级场景”推进一秒，基础时钟 / 传送带 / 增量帧测试直接调用半秒转换，避免隐藏时间单位。
