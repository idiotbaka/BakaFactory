## 手动验收

1. 根目录执行 `npm run setup`、`npm run dev`，打开 `http://127.0.0.1:5173`，确认 `Persistent Factory`、`Server: Online`、SQLite Ready 与版本。
2. 请求 `http://127.0.0.1:8080/health` 与 `/api/v1/health`，检查 HTTP 200、JSON 字段和 `X-Request-ID`。
3. 使用 POST 请求 `/health`，应返回 JSON 405 与 `Allow: GET`；访问 `/api/v1/missing`，应返回 JSON 404 与相同 header/body request ID。
4. `Ctrl+C` 停止开发服务，单独执行 `npm run dev:web`，刷新应显示 Offline；在第二个终端执行 `npm run dev:server`，点击“检查连接”恢复 Online。
5. 停止服务，执行两次 `npm run migrate`，两次均成功；再次启动，数据库 metadata 初始化时间不变。
6. `npm run check` 应通过；`npm run build` 后执行 `npm start`，打开 `http://127.0.0.1:8080` 确认 production 页面在线，数据库文件独立。

## 当前限制

- 不包含阶段 5 之后的生产、物品运输、模拟循环、离线收益或 MMO；当前支持静态建筑编辑。
- Go 修改后需重启开发命令；前端支持热更新。
- `.env.example` 为配置说明，Go 不自动加载 dotenv。
- SQLite 为单实例方案，尚未做多进程负载与生产性能验证。
- 阶段 1 仅验证基础服务与数据库连通，认证和生产逻辑在后续迭代中实现。
- migration 仅向前；恢复旧程序须检查 schema 兼容性，不能修改已应用 SQL。
- 首次 setup 需要可用的 npm / Go 网络源。
- production 账号需 HTTPS；浏览器本机 HTTP 验收使用 local 开发模式。
- 账号限流为单进程内存状态；尚无找回密码或全部设备登出。详细边界见 auth.md。
