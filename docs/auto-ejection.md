# 生产机器自动弹出

## 范围与交互

有加工配方的生产机器可在模组检视的设备启停按钮下方切换“自动弹出”。默认禁用；是否启用记录在实例 `configuration.auto_eject`，移动、旋转、切换配方、本机保存和云备份均保留。仓库、带、投料机、箱子、垃圾提取口与纯能源设施继续使用原有规则，不新增此开关。

开关编辑不重置配方、加工进度、能量、冷却或缓存。全局暂停时不能编辑；设备自身暂停时不主动弹出，投料机仍可按原规则取走已完成产物。已完成产物无需额外动力即可弹出，不改变机器加工耗能。

## 每半秒行为

每 tick（0.5 秒游戏时间）尝试一次，仅取产物格中的固体；不取输入、燃料，不运输散装流体。一次最多成功一种物品、最多 6 件，按产物栈现有顺序尝试可接收物品。某个产物被过滤或目标该物品已满时，可尝试后续产物。

- 1×1 只检查箭头正前方一格，不能向后方、侧面或隔格输出。
- 2×2 只检查朝向一侧的两个外邻格，按本刻物流轮换顺序尝试可行目标；整台共用一次行动与最多 6 件，不因尺寸翻倍。目标是多格建筑时按实例去重。
- 空格、拒收或满载不扣物品，下一刻重试；其他路线本刻已预留的目标容量也要扣除。
- 保持每种物品一格 / 每格 100 件，已有同种未满格可继续补入。

| 目标            | 接收规则                                                                                              |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| 传送带          | 按带容量截断，例如初阶 / 机械带最多 2 件，其他带也不超过单次 6 件；遵守启停、供能、过滤及完整腾空依赖 |
| 生产机器        | 仅送往当前配方接受的输入缓存，不自动切配方，不使用燃料通道；外部补料不要求目标供能的原规则保持        |
| 料箱            | 遵守输入过滤、格数与每格上限                                                                          |
| WH / 收货终端   | 遵守输入面 / 过滤及总库存安全上限；真实入仓计入自动化入库统计                                         |
| 地下入口        | 必须接在入口后方，同一事务预留配对出口；不向出口反向塞货，不增加中间载荷或地下载荷动画                |
| 投料机 / 分流器 | 不向其内部存货，仍由投料机主动从后方机器取货、交给其前方目标                                          |

散装流体继续走管道；轴 / 线缆等无固体缓存设施不接收。每刻先生产结算再统一固体物流，刚完成产物可参加本刻输送，物流新到货不能同刻再次跨一格。

## 竞争与物品守恒

自动弹出只在 `local/logistics.ts` 添加候选路线，不另起结算循环或计时器。

1. 路线读取同一份转移前库存，投料机提取同一机器的产物时优先预留，自动弹出只能用余量；多个投料机保留原轮换、批次与冷却。
2. 共用来源扣减、输入 / 箱格容量及单一带载荷预留，不重复承诺同份产物或容量。
3. 目标带须在最终方案中完整腾空，部分提取不算腾空；撤销阻塞候选后重建预留，也可让大机器改试同一朝向另一外邻格。
4. 确认最终方案后统一先扣后收，不提前改库存 / 冷却 / 动画；机器人随后读取实际剩余库存。
5. 地面转移复用 `transfers`、稳定载荷 ID 与共享动画时钟；开关 / 移动 / 删除取消失效路线，无额外 RAF 或动画结算。

## 配置与兼容

`local/machineOutput.ts` 统一机器范围及 6 件上限，配置缺失等同关闭。Worker 行业操作、客户端读档和 Go 云存档校验严格要求布尔值及配方型生产机器；拒绝 null、字符串、数字及其他设施上的该配置。

复用现有开放的 `configuration` 对象，不新增 API 消息结构、存档版本或数据库迁移。旧档不自动开启，不更改目录、配方、产量、工时、动力需求或物流定义。
