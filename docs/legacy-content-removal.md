- 删除 3 种物品、6 种设备 / 物流、3 条配方及 legacy 目录字段、隐藏筛选、旧配方自动选择与旧物品专用绘制。保留当前设备复用的通用图标类别（如 assembler / furnace / conveyor）。
- 含已删除 ID 的旧测试存档不再支持；本机与云备份沿用未知物品 / 设备 / 配方校验，拒绝并保留原档，不静默删物、不自动替换、不清理账号或数据库。
- 现行物品的历史时钟、总仓库与任务版本升级继续保留。已发布 SQL migration 和数据库历史升级测试保留，不修改内容或 checksum。
- 相关模拟、编辑、物流动画与云备份测试改用当前目录；导入脚本不再从上一份生成目录携带早期测试内容。
- 美术历史原图与裁切槽位记录保留，重建脚本按当前目录过滤导出，移除旧物品别名与专属提示词；不会重新导出已删除 ID。独立补充物品的现有贴图保留。重建脚本本轮未执行。

## 用户验收

1. 运行 `npm run dev`，用当前六阶段存档进入工厂；图鉴、仓库搜索、物品来源和开发者物品获取不应再出现表中条目。当前基础铁板、简易齿轮等名称相近物品继续可用。
2. 在开发者物品获取中选择 I0001 / D0001 等当前物品，确认入仓、切厂、刷新与云备份保持。
3. 检查现行机器选配方、初阶带 / 投料机、移动 / 回收与动画行为；没有配方的机器必须手动选择配方。
4. 仅用隔离的测试快照分别植入表中物品、建筑或配方 ID，确认本机 / 云端校验拒绝且不覆盖原存档。不要修改真实存档或删除数据库。

检查命令：`npm run import:gameplay`、`npm run generate:api`、`npm run lint`、`npm test`、`npm run build`。自动 / 浏览器 / HTTP 冒烟测试由用户执行，实际状态见 [progress.md](progress.md)。
