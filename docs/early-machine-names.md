# 前期自动设备与工作室手工功能命名

## 名称与范围

六种实体建筑与对应设备道具统一使用下表的自动设备名，物品不再为这六项添加“设备·”前缀，分类仍为设备道具。工作室 Tab、工作室配方卡的加工方式、工作室入口和机械手订单的手工工序单独使用手工功能名。设备名称不能直接当作工作室 Tab 的显示名。

| 建筑 ID | 设备物品 ID | 实体建筑 / 设备道具 | 工作室手工功能 | 开放条件           |
| ------- | ----------- | ------------------- | -------------- | ------------------ |
| m02     | i0061       | 自动分拣台          | 手动分拣台     | 初始开放           |
| m07     | i0051       | 自动铁砧锻台        | 手工铁砧锻台   | 初始开放           |
| m01     | i0062       | 自动工作台          | 手工工作台     | 初始开放           |
| m03     | i0017       | 自动拆解台          | 手工拆解台     | 首次制造自动拆解台 |
| m04     | i0026       | 自动破碎机          | 手摇破碎机     | 首次制造自动破碎机 |
| m08     | i0052       | 自动装配台          | 手工装配台     | 首次制造自动装配台 |

地图设备仍需实际制造并安装，由物流投料后自动加工，保持原来的免能耗、配方工时、容量和安装规则。工作室初始三项开放不表示赠送三个实体设备。后三项以累计真实制造记录永久开放，不要求安装、不消耗解锁道具，也不以任务领奖或仅持有 / 拆回道具代替首次制造。

P1 三条首造任务的描述直接写明“自动设备（首次制造后解锁工作室中的对应手工功能）”。任务 ID、目标物品 ID、条件、奖励和阶段推进不变。道具 / 建筑介绍和来源卡同时说明自动加工用途与手工解锁；来源显示“加工设备：自动装配台”，工作室入口显示“工作室 → 手工装配台”，不再使用“同名分类”提示。

初阶传送带的物品 `i0053` 和建筑 `hand_belt` 同步更名，配方 R1033、奖励与全部当前文案引用使用“初阶传送带 / 初阶带”。内部 ID、贴图及免能耗 / 容量 2 / 每格 2 tick（1 秒）保持。

## 实现与兼容

- `apps/web/src/game/earlyMachineNames.json` 是六组名称的共用映射；UI 的 `local/workshop.ts` 导出 `workshopMachineName`，工作室和手工来源导航统一调用。
- `scripts/import-gameplay.mjs` 用原机器 / 道具名称建立一次性显示名替换，并允许 `docs/quests.json` 使用当前名称解析同一物品 ID。原名仅保留给读取未修改的 v0.9 原案；运行目录按当前名称生成，不创建额外物品、建筑或配方。
- `scripts/gameplay-copy.mjs` 生成自动设备用途及具体手工解锁说明。目录名称、物品描述、配方输出标题、任务描述、图鉴、仓库、来源 / 配方下拉、地图提示、施工与诊断从同一运行目录读取。
- `scripts/generate-search-index.mjs` 同时收录当前目录名和六个手工功能名；自动设备、初阶传送带与手工名称均有正确的拼音索引，旧建造名称不作为当前目录显示名。
- 修改数据后执行 `npm run import:gameplay`，不手改 `apps/server/internal/catalog/definitions.json` 或原始设计 JSON。更新目录需重启 API 并刷新前端，开发时可由用户重新运行根目录 `npm run dev`。

只改显示文案与手工导航名称。存档按稳定 ID 引用，已有机器身份、布局、配置、库存、手工队列、制造记录、任务进度和贴图均沿用，不需要迁移或清档。地图三字简称保持原功能短名，完整提示显示新名称。v0.9 原案、带日期的历史进度及美术生成历史输出保留原记录供溯源。

导入前后已对目录剔除 name / description 后的结构进行静态比对，所有规则字段一致。实际检查和编译状态见 [progress.md](progress.md)，游戏内步骤见 [前期命名验收](acceptance.md#前期自动设备工作室手工名称与初阶传送带待用户执行)。
