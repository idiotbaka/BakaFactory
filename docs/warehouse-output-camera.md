# 仓库输出件数与相机连续性

## 输出件数

WH 的每个面在“输出”模式下显示“输出件数”，取货终端提供单个同名选择框，均为整数 1～20，缺省 1。复用 GameSelect、最小文字 12px；输入 / 关闭面隐藏控件但保留其值，改物品不重置。暂停时不可修改。

配置保存在原实例 configuration：WH 为 face_0 / face_90 / face_180 / face_270 内可选 output_count，取货终端为顶层可选 output_count。仅表示单次成功输出的最大件数，不要求凑满，不预扣物料、生成缓存或免费物品。旧档缺字段按 1 读取，完整本机 / 云备份保存。两端拒绝 null、字符串、非整数、超出 1～20 的数，以及不支持设施上的该字段；沿用格式 / 规则版本，无数据库迁移。

实际单批取库存余量、设置件数、取货设备批量、目标容量及其他预留量的最小值，各面 / 各厂竞争同一库存仍先预留、后统一扣收。目标只余 7 件空位且设置为 20 时送 7；初阶带容量 2 时最多送 2；拒收 / 满载不扣库存、不画成功收据。

- WH 自动直接输出仍每秒一批，各面上限独立。投料机取货同样受该面件数与投料机自身批量 / 间隔限制；缺省 1 也会约束此前投料机绕过 WH 单批限制的路径，不因加大堆叠增加动作次数。
- 取货终端仍每秒最多一次成功行动，一批只含一种物品；最多两物品按成功轮询，缺货 / 拒收跳过。只改件数不重置游标 / 冷却，投料机不能绕过终端件数。
- WH 流体保持原每秒一次时机，单批受该面件数与管道每半秒流量 / 容积限制，不把堆叠数转为额外半秒动作。单介质、旧容积预留和新到货不再跨格保持。
- 机器人在原秒级装卸工时后取货，同时受 WH 该面件数和机型载重限制；同刻自动物流已使用该面时保守让出，多机器人共用面预算。站点、能源、路径和任务工时保持。

入口：local/transportConfig.ts 统一缺省 / 上限；transportActions.ts 保留各面旧值；logistics.ts / fluids.ts / robotFreight.ts 约束出库；Go domain/transport.go 校验云备份。协议在 docs/openapi.yaml，类型由 `npm run generate:api` 生成。目录文案在 scripts/gameplay-copy.mjs 维护，再由 `npm run import:gameplay` 导入；不改原案或配方。

## 相机连续性

厂区间共用当前视角。FactoryEditor 不再按厂区 ID 重建，切厂保留平移、缩放和组网显示，仅清除旧厂选中、悬停、菜单、地下端口预览及未完成手势。旧厂异步编辑响应不再将旧选择发布给当前厂。主动“适应地图 / 居中放大”和明确定位机器 / 机器人仍生效。

首次可见时在 useLayoutEffect 读取真实视口并居中，定位前隐藏地图内容，避免先绘制 x=0 / y=0 的网格再跳到中心。初始停在其他 Tab 时跳过零尺寸，返回工厂后才初始化。后续隐藏 / 恢复保留最后非零尺寸与相机，显示前校正尺寸，不重复居中或重放同一定位请求。

ResizeObserver 在窗口改变 / F 沉浸折叠时按视口宽高差的一半补偿平移，保持同一世界点在屏幕中心；零尺寸或隐藏状态不作为新基准。观察器 / 输入监听只创建一次，通过最新操作引用读取当前厂，无新 RAF、定时器、浏览器持久化或游戏存档字段。
