# 当前架构

机器人检视与管理运输表单共用工作台按机体 ID 保存的页面草稿；地图两步选点只回填草稿，不发送库存操作，跨厂切换保留机体 / 来源。新端点白名单由 UI 与 Worker 复用；任务空 item 表示不过滤，Worker 按真实候选选择单种货物并经原 exchange 原子扣收，Go 云备份仍验证实际 cargo 与机型。无新增存档字段 / migration，协议说明已生成，见 [机器人操作](robot-operations.md)。

机器人通行规则统一到 `robotMovement.ts` 与 Go `robot_movement.go`：实际寻路、部署 / 落点、编辑预览 / 原子校验及存档允许带管线重叠，活动蓝图仍阻挡。当前厂批量路径共享占格索引并按世界快照缓存，静态障碍缓存依附不可变布局；稳定 ID 的独立位图层复用共享 RAF，仅插值确认位移，不增加库存 / 任务 / 网络消息。旧工时在校验后克隆中收敛；既有机器人载量上限扩为 100、站点需求 / 实供与补给上限扩为 1500 kW，普通设施仍限制 1000 kW，OpenAPI 已同步，无新增接口 / 字段或数据库迁移，见 [机器人重构](robot-upgrade.md)。

页面隐藏不再撤销运行许可，后台继续逐刻生产和保存、仅停止 RAF 绘图。Worker 额外每约 10 秒发送 heartbeat_due，由主线程复用会话心跳；短延迟按到期时间顺序执行最多 5 刻，单调 / 墙钟任一唤醒间隔超过 2500ms 则暂停并重新校验。许可携带墙钟截止时间防止排队延长授权，freeze / pagehide 与恢复事件保留基本暂停保护，无新 API / 存档字段 / 迁移。实现、边界与验收见 [后台生产](background-production.md)。

WH / 取货终端单批输出件数复用实例 configuration，WH 各 face_N 和取货终端顶层的 output_count 可选、整数 1～20、缺省 1。Worker 原子复核编辑，固体 / 流体 / 机器人读取同一上限，客户端与 Go 云备份校验同步；OpenAPI 明确可选字段并生成类型，旧档无需迁移。相机仅保存在持续挂载的 FactoryEditor 内，切厂不重建，首次测量和 Tab 恢复校正在绘制前进行，不进入 Worker / 存档，见 [输出件数与相机](warehouse-output-camera.md)。

仓库分钟统计在 Worker 世界转换边界，通过真实 inventory.store 采样已绑定的唯一仓库，按实际厂区合并进出，并从触及物品的前后总账计算净变化。主厂可选 warehouse_activity 保存最多 120 个稀疏 tick 桶，本机 / 云存档携带，旧档从当前 tick 开始预热；机器人自动提案失败样本随库存一起撤回。WorldFrame 只发当前桶，主线程裁剪并追加历史，无新定时器或数据库迁移；协议与两端校验同步，见 [仓库分钟统计](warehouse-activity.md)。

开发者物品获取使用 `WorldAction.developer_grant_item`，由现有 Worker 串行执行 `actWorld`：在克隆世界中验证当前物品与正安全整数数量，通过 `store` 检查相加溢出后仅更新主厂总仓库，并记录 discovery、同步获得类任务及递增 revision。失败不提交克隆。`GameRuntime.world` 要求开发者入口已开启，正常在线许可 / Worker 暂停检查继续适用；成功结果通过既有完整快照与 IndexedDB 保存流程发布，库存随正常云备份上传。仅新增客户端操作，无 HTTP 协议、存档字段、版本或数据库迁移。

机器通过 `auto_eject` Worker 行业编辑保存实例 `configuration.auto_eject`，客户端与 Go 均限制为配方型生产机器的可选布尔配置。固体规划器新增正前缘候选，与投料机共用来源 / 容量预留、腾空依赖、先扣后收及动画收据；无新计时器、API 结构、存档版本或数据库迁移，见 [机器自动弹出](auto-ejection.md)。

图鉴固定筛选区和来源配方卡仅修改客户端布局。`ItemInfoProvider.onWorkshopRecipe` 向 `IndustryViews` 传递配方 ID，主视图维护临时目标、切手工设备、清搜索，再按吸顶栏实际高度滚动中央容器并聚焦配方卡；不滚动整个页面、不发 Worker 操作，也不新增 API / 存档字段。设计与验收见 [图鉴与配方导航](recipe-navigation.md)。

内置 WH 的位置现由同一实例坐标决定，可长按移动、朝向固定且不可删除 / 新建。主厂与各分厂的唯一 WH 校验不再要求原点；总仓库账本与库存归属保持。机器人跨厂出入口、过境校验和新增终端选位使用实际 WH，过境中的来源 / 目标仓库暂不可移动，无协议字段或数据库迁移，见 [工厂仓库移动](warehouse-move.md)。

物流玩法更新：自动投料机默认半秒 20 件，所有厂顶部开放不限阶段配额的垃圾提取口，两端存档 / 蓝图同步校验；机器人每刻走格、整秒处理作业与过境，流体每刻按原批次转移，泵按半秒供能。载荷计数复用原物品 DOM 与帧时钟，无新存档字段 / 数据库迁移；见 [物流玩法调整](logistics-upgrade.md)。

2 TPS 的时间单位、按秒动作的设施、协议精度及旧档转换见 [2 TPS 与传送带](simulation-time.md)。这是全运行层共用时基，开发者倍速只改变真实调度频率。

地下传送带通过本地 Worker 的 `place_underground` 编辑一次创建两个互相引用的实例并扣除一套道具；移动、成对回收及载荷返仓沿用原子克隆与唯一总仓库。`configuration.underground_role` / `underground_peer` 与既有带缓存保存配对和载荷，客户端与 Go 均验证完整同厂配对，无协议字段或数据库迁移。地下段只是固体物流规划器中的路由边，不模拟中途节点或轨迹；详见 [地下传送带](underground-belts.md)。

仓库 IO 使用 Worker `submit_quest` / `upgrade_io` 原子世界操作，实际提交材料后记任务完成，领奖开放设施。终端通过固体物流预留 / 扣收 / 成功收据访问唯一总库存，数量从各厂实例派生。OpenAPI 新增任务种类、关键标记、机制奖励与取货轮询游标，两端校验配额 / 领奖 / 配置；旧档无终端保持零级，无数据库迁移。详见 [仓库 IO](warehouse-io.md)。

读取本机 / 云存档的 validateSave 入口携带诊断来源；失败打印 `[BakaFactory] 存档校验失败` 与 source / path / reason，并对带载荷细分 ID、物品、进度与容量原因。日志仅含定位字段和必要的局部诊断，不输出完整存档、账号或会话凭据；内部未指定来源的校验默认静默。缺失物品类型、未知物品、非法数量及其他格式错误均拒绝读取并保留原档；不自动删除异常载荷 / 缓存 / 仓库条目，也不调整入库统计。详细日志只负责定位，不包含针对开发热更新中间状态的兼容分支；既有已发布格式的正常兼容规则保持。

固体物流规划器按路线保存上游多物品候选，逐项验证目标容量 / 过滤 / 配方 / 通道与本刻来源预留，失败不占本次动作。向已有载荷的带预留后若不能完整腾空，排除失败路线并重建临时预留，供同一设备其他分支或其他设备继续尝试；堵塞且无其他提取路线的带链批量排除。只有最终全部依赖满足的方案才统一扣收、设置冷却和生成 transfers，不改纯单刻 / Worker 原子模型、HTTP 协议或存档。设施范围与保留的流体 / 机器人约束见 [simulation.md](simulation.md#固体物流的候选物品与阻塞)。

开发者模拟倍速由 `GameRuntime` 当前页面的 `GameView.tickRate` 管理，默认 2，打开工具并在线运行时可设置 2～60 的整数。`permit` 向 Worker 携带速率和原真实时间许可，模拟定时器按 `1000 / TPS` 的到期时间逐刻调用同一 `stepWorld`，短延迟单次最多补齐 5 刻，另有独立 Worker 心跳定时器；切速率替换待执行定时器，相同速率心跳不重启计时。参数 / 验证集中在 `local/tickRate.ts`，不放入 `WorldAction`、GameSave、IndexedDB 元数据或云备份，`simulation.tick_rate=2` 表示每刻 0.5 秒游戏逻辑；旧 1 TPS 存档读取时升级。关闭开发者工具恢复 2，暂停 / 恢复保留本页所选速率；刷新 / 换账号新建运行层默认 2。顶部 HUD 和动画读取临时速率，心跳 / 许可 / 云备份继续按真实时间运行，不改服务器或数据库。验收见 [acceptance.md](acceptance.md)。

名称搜索为纯客户端展示逻辑：开发依赖 pinyin-pro 在 `scripts/generate-search-index.mjs` 中读取运行目录，为物品 / 建筑 / 配方 / 机器人模型名称生成唯一全拼和首字母索引，前端共用 `catalogSearch.ts` 做归一化后的连续子串匹配；完整词库不进入浏览器或 Worker。玩法导入、开发启动、前端 build / test 自动生成，lint 校验一致性，不改玩法原案 / 运行定义、API 或存档。未知动态名称仅按原文 / ID 搜索。方案、数据流程与新增内容维护见 [search.md](search.md)。

机器可选占地：36 台复杂配方机器的目录增加 supported_sizes=[1,2]；实例 / 放置 / 蓝图的可选 size 缺省 1，2×2 坐标为左上角。前后端存档校验完整占格，Worker 的放置、物流、能源、机器人路径与蓝图共用对应几何；不改变实例数、安装道具数、缓存、配方工时、物料或产能。旧存档保留原单格，不需迁移，完整设计见 [machine-footprints.md](machine-footprints.md)。

工厂入口新增静态资源门槛：useLocalGame 订阅页面内共享的 AssetPreloader，等待同源 Fusion Pixel 字体的实际 FontFace 与全部物品 / 建筑图标读取解码完成，再创建 GameRuntime、读取账号存档锁 / IndexedDB、校验在线与云备份、启动 Worker。进度按真实完成项计算，最后一项为原存档 / 在线初始化；失败保留进度重试。卸载 / 退出后的迟到预热不会启动旧玩家运行层，公开静态缓存不包含账号数据，不改持久化或生产规则。详见 [fonts-and-loading.md](fonts-and-loading.md)。

Go 的生产 FileServer 对成功的 Vite 八位内容哈希资源和版本化 Fusion Pixel 字体设置一年 public / immutable 缓存；入口 HTML、favicon 与其他未版本化文件使用 no-cache，每次复用前校验。仅静态 200 / 206 / 304 可覆盖全局 no-store；API、健康检查、重定向与静态错误仍 no-store。nginx 默认透传，不统一覆盖 Cache-Control 或开启账号共享缓存；发布时保留旧哈希资源，不原地改写版本化文件。完整边界及步骤见 [static-assets.md](static-assets.md)。

建筑 / 物流美术属于客户端显示层：75 张 128px PNG 与 12 个代码外观覆盖全部 87 个目录 ID。DefinitionIcon / BuildingSprite 提供 GUI，BuildingVisual 提供地图与预览；buildingConnections 复用原方向邻接选择，routeGeometry 缓存整数 SVG。贴图索引和几何独立分包，图片以外部 URL 缓存；颜色 / 端口 / 液位只读目录、布局与确认状态，不增加 Worker、API、数据库迁移或存档字段。详见 [building-art.md](building-art.md)。

物品贴图为客户端静态资源：按稳定物品 ID 查找 128px PNG，GUI 与传送带共用 ItemSprite，阶段脚下光影只读资源清单中的 tier。资源索引单独分包、PNG 独立缓存，不进入 Worker、GameSave、IndexedDB 或云备份，不修改定义与迁移。传送带只替换原 payload 节点内部图形，继续消费原成功收据与共享帧时钟；素材流水线见 [item-art.md](item-art.md)。

开发者工具入口显示偏好为 LocalRecord.developerToolsVisible，可选布尔值、缺省 false，按账号同工厂记录串行写入 IndexedDB。GameRuntime 提供只读状态与串行切换方法，保存成功后发布 GameView；普通 tick / 编辑继续携带同一元数据，失败沿用暂停 / 重试保护。该字段不进入 Worker、GameSave 或云备份，恢复云档保留当前浏览器偏好。登录工作台只暴露 `window.bakaFactory.devTools()` 查询 / `devTools(true|false)` 切换入口，退出 / 换账号后清理并废止旧句柄；不暴露运行层对象或新增账号权限。隐藏入口与 industry.developer 的实际功能测试设置相互独立。

P2 任务在主厂 industry.quests 增加可选的 factory_produced / warehouse_received 逐物品统计和 factory_events 真实事件账本；Worker 在生产 / 运输 / 扩建的成功原子转换中写入，随完整存档和增量行业状态保存。OpenAPI、TypeScript 和 Go 同步校验安全整数、已知物品 / 事件及缺省兼容；新统计不从旧库存推算，不改变规则版本或数据库。阶段仍由终局领奖推进，已解锁阶段不回退，具体边界见 [quests.md](quests.md)。

## 共用总仓库（规则版本 3）

所有厂区 WH 连接同一库存，主厂 simulation.warehouse 是唯一持久账本，分厂 simulation.warehouse 必须为空对象。projectFactory 将总库存投影到当前厂视图；WorldFrame 只随主厂发送一次库存，安静分厂无需重复发送。每世界 tick 克隆总库存一次，分厂模拟临时使用这份当前账本顺序扣收，完成后移除临时库存；编辑分厂同样克隆 / 验证并原子提交总账。前一快照不会被新 tick、机器人或失败编辑改写。

WH 端口、流体方向、过滤、速率和设备输入 / 产物缓存仍按厂独立；机器不自动吸取总仓物料。建造、手动补料、燃料、拆迁 / 收取、任务奖励、机器人本体 / 附件 / 备件和施工设备均扣收总仓。智能派单按全世界单一 WH 物品库存预留，不能借不同 WH 重复承诺。机器人仍需真实站点、授权、路径与工时；本轮不重新设计其定位。

GameSave 保持 format_version=1，写 rules_version=3。客户端读取 1/2 时先完整校验，再在克隆中按物品加总所有仓库并清空分厂库存；机器缓存、管内流体、燃料、机器人携货和订单私有物料不纳入合并。总和超安全整数则拒绝并保留原档，不截断 / 丢弃。版本 3 拒绝分厂非空仓库，刷新 / 云恢复不会再次相加；Go 兼容校验 1/2/3、只读保存完整世界，不改数据库。拾荒、工作室加工、仓库下单及顶部取消开放到所有厂区，全部路由到主厂唯一 industry.workshop 和总仓库；只有主厂每世界 tick 推进一次，切厂不建立队列或重复加工。

开发测试选项保存在主厂可选 `industry.developer.warehouse_orders_always_available`，缺省关闭，随 IndexedDB / 云备份 / 行业增量帧保存。`developer_settings` 是 Worker 串行世界操作，任意厂区可修改唯一设置；两端严格验证布尔值 / 对象字段，不新增账号权限或 HTTP 接口。下单访问可由任务领奖或开发开关开放，阶段门槛始终只认原任务 / 里程碑。未领奖时进行中的订单要求开关保持开启，关闭请求原子拒绝，先完成或取消后可关；因此读档仍校验队列具备实际访问权限。

仓库订单复用主厂唯一 `industry.workshop`，不启动新 Worker / 定时器。`local/orders.ts` 是主线程预览与 Worker 确认共用的有界纯规划器；确认签名仅比较计划一致性。Worker 在克隆世界内重新规划、一次预留仓库材料并保存 order（目标、数量、工序、指针、私有库存），逐批实际转换物料，完成 / 取消原子入总仓库。两端读档从私有库存重放剩余链检查数量、权限及溢出，读取不结算；云备份接口携带同一完整订单。规则版本保持，旧 P2 无自动入库字段的档补认机制解锁，详见 [warehouse-orders.md](warehouse-orders.md)。

本项目采用客户端权威运行：浏览器以 2 TPS 推进工厂，IndexedDB 是本机存档，Go / SQLite 提供账号、单点登录校验和每账号唯一云备份。入口见 [index.md](index.md)，规则见 [simulation.md](simulation.md)。

剧情观看 / 待播状态为按账号的 LocalRecord.viewedStories / pendingStories 可选展示元数据，同工厂记录串行写入 IndexedDB，建厂前 save=null 亦可保存开场完成。P1 只在确认快照出现新的 p1_free_hands 领奖时入待播队列，同一事务保存领奖与待播；旧档加载 / 兼容与云恢复不补造事件。刷新可继续待播，完成事务成功后才发布已观看并关闭，运行 tick 不抢先移除。两字段不进入 Worker / GameSave / 云备份；云恢复保留观看历史并清理不再满足领奖条件的待播项。重放按实际 claimed 开放，不以开发者下单开关替代。无 API、Go 或数据库迁移，详见 stories.md。

开放任务定义由 docs/quests.json 经玩法导入进入 catalog.quests，stage_final 标记 P1～P5 唯一终局；主厂 industry.quests 保存完成 / 领奖 ID、实际工作室批次与自动入库数。新进度写 stage_quests_version=1，仅按依次已领奖的终局推导 stage；制造里程碑与配方前置独立保留。终局的同阶段普通任务半数门槛由 UI 与 Worker 共用规则，普通任务先结算，隐藏目标不能直接领奖。claim_quest 原子发奖至主厂并推进，重复 / 溢出拒绝；增量帧与云备份共用账本。两端校验可选版本与新阶段一致性；无版本旧档先按旧规则只读校验，再在客户端克隆升级、只补认已经跨过阶段的终局，不退阶段、不发奖励或制造普通历史。兼容在运行时通知 / 剧情基线建立前完成，云恢复不伪造事件。沿用格式 / 规则版本，无数据库迁移。详见 quests.md。

图鉴曾获得记录为主厂 `industry.discovered_items` 可选物品编号集合，随完整本机 / 云存档及增量行业状态传递，按账号与世界隔离。实际拾荒 / 提取及制造成功后记录，耗尽不撤回；不计入 crafted、里程碑或库存。旧档缺字段时从制造记录、各厂现有实物 / 分仓留存键、队列原料与机器人附件补记，无法证明且已无痕迹的旧历史不猜测。只在读档补记，不每 tick 扫全世界。客户端与 Go 拒绝重复 / 未知物品和 null，沿用当前兼容版本，无数据库迁移。

工作室批量队列仍只存起始厂 industry.workshop，开工预留 1～100 批全部原料，主厂每 tick 只推进 0.5 秒，逐批结算 / 减 remaining。total 保留本次提交总数；取消只返剩余批次。两端校验可选计数成对出现及范围，旧无计数队列按单批处理。顶部从共享行业状态显示同一进度；`GameView.workshopBlocked` 从完整主厂库存派生，不能因切到空分仓就把产物上限等待显示为正常工作，不写存档 / 云协议。沿用当前格式 / 规则版本，无数据库迁移。

手工每批耗时通过 `local/workshop.ts` 的 workshopDuration 派生为 `max(1, floor(duration_ms / 2000))` 秒，Worker、配方卡、顶部进度和来源说明共用，地图机器仍读原 duration_ms。客户端与 Go 存档校验保留原配方工时范围，以兼容加成前进行中的队列；读档不改库存 / 进度，若旧进度已达新工时，下一获准运行 tick 最多完成当前一批并将下一批置零，暂停 / 产物上限等待仍不结算。HUD 仅将可视进度限制在新工时内，不回写状态，也不因换端重复扣料。

额外工作室权限由 `local/workshop.ts` 与 Go `domain/workshop.go` 判定：初始设备始终可用，M03 / M04 / M08 额外要求对应安装道具累计制造 ≥ 1。UI 子分类、Worker 提交、客户端读档及 Go 云备份结构校验保持一致，复用已有 crafted，无新增存档字段、API 类型或数据库迁移。新增设备配方仍走唯一 industry.workshop，不创建第二队列、地图实例或免费原料。

## 增量快照、索引与诊断（F）

初始化、编辑 / 切厂、建厂和云恢复返回完整 state；普通 tick 发送 `WorldFrame`，包含基准 / 新 revision、同一 tick、行业进度、机器人以及各厂模拟更新。布局数组未改就不传；只有空闲 WH 的分厂复用机器状态，只传厂 ID / revision，主线程补同一 tick。安静分厂保留空仓映射，总库存只在主厂克隆一次，机器人交货不会改旧世界；施工完工更换布局数组并使端点索引失效。

`applyWorldFrame` 在主线程构成完整新世界，拒绝丢帧、错序或缺厂，失败暂停并保留上一有效快照。完整本机 / 云存档格式不变，每 5 秒游戏时间（10 tick） 自动保存完整世界；慢写入合并为一个最新待保存意图，编辑、手动上传和关闭仍显式写入完整状态。不是只保存当前视口，也不降低远厂模拟频率。行业进度每世界 tick 仅克隆一次，分厂顺序共享这份新账本；原世界不被消费或修改。

世界内 factory / endpoint 按实例索引查询；跨 tick 只复用不可变布局，施工提交主动失效缓存。自主派单在一刻开始建立需求 / 来源承诺索引，成功指派后同步追加，保留原有轮换和预算。`Observations` 保留最多 60 秒（120 tick） 的制造差量、固体 / 流体逐格转移及完成搬运趟数；编辑、重复读取和暂停不采样，初始化 / 云恢复重置，观察数据不写云存档或游戏状态。

`diagnostics.ts` 只读当前投影和共享行业进度，报告实际库存缺口、整批产物容量、工作条件、供能和物流 / 机器人等待；名义速率来自启用设备所选配方，实产来自确认的制造账本差量，不互相替代。终局直接读取永久首次制造里程碑和许可证制造记录，不依赖当前仓库仍有本体。性能入口及仍需实测的复制 / DOM / IO 边界见 [performance.md](performance.md)。

## 机器人检视与只读路段（E2e）

`robotLifecycle.ts` 统一忙碌 / 实际归属站 / 必需厂区及状态说明；正在使用的厂区授权在界面锁定，Worker 仍作最终原子校验。`robotFreight.ts` 的 robotDestination / robotJourney 供实际行动与 `robotNavigation.ts` 共用，阻塞时区分静态无路和机器人占格等待。暂停、过境、已卸货仍返站及施工回收使用同一份真实状态，无新增存档字段或数据库迁移。

工作台持有临时机器人选择和中央 Tab，地图点击与全局列表同步，右侧 `RobotInspector` 保持原固定列宽。列表可搜索、按当前厂区 / 等待状态筛选，定位跨厂机器人时走既有切厂动作，过境定位确认落点；不同厂区的切换仍需有效在线许可。本地 `runtime.robotRoute` 从已有完整快照派生一个选中机器人的下一路段，useMemo 随新快照或选择更新，不增加 Worker 全世界广播或网络请求。主线程从增量帧重建完整世界；地图通过 runtime.robotRoutes 批量计算当前厂路段，按快照缓存且选中检视复用，不以有界路径计算代替性能实测。

路段按实际 WH 面、蓝图障碍和当前机器人占格计算，只读显示当前厂可经过带管线的路径 / 下一 WH，过境只显示确认目的地与余秒。路线不是预约，不修改 revision、库存、能量、账本或存档；未来占格与目标配置变化可能使其失效。地图选择 / 定位同厂在暂停时可用，任务操作继续受在线许可约束。机器人 / 施工 / 返程 / 工时继续由 Worker 串行推进，客户端图形不结算行动。

## 蓝图施工（E2d2）

`construction.ts` 在世界动作克隆中预留一台设备的完整占格蓝图，并从归属 WH 扣 1 实际设备存入机器人唯一 cargo。复用 `placement.ts` 安装约束和 `robotRoutes.ts` 空地 / 跨区路径；蓝图为派生占格，不创建提前工作的建筑或模拟缓存。新增蓝图须可达、预留返程能量且不能堵断其他机器人的安全返程；编辑、部署和过境落点也避让蓝图。

`robotFreight.ts` 在生产 / 物流之后推进现场 10 秒工作，完成时同时移除 cargo / construction、替换目标厂 buildings 数组并创建空 MachineState。既有布局快照不会被原地追加，设备从下一 tick 参与生产。中止保留 construction 和 cargo、释放预留格，实际归属 WH 交货后再回补能站清除任务；无新增作业凭据。OpenAPI RobotConstruction 与 Go `construction.go` 检查类型 / 阶段 / 配方 / 许可 / 实物与预留冲突，兼容旧无施工字段存档，无数据库迁移。多台可并行，每台只有一个在建蓝图，批量多格排程不在本阶段范围。

## 确定性调度（E2d1）

`robotAutonomy.ts` 在异常同步后、实际机器人移动前规划任务，复用原有指派内核；所有操作仍在当前世界克隆上。输入需求 / 来源库存计入现有任务预留，现场按任务类型排他，失败提案恢复该机器人与总仓库。只有智能机器人、启用的自主权限、允许厂区与真实归属站停靠才能发起；新提案有共享访问预算与 5 tick 周期，不依赖墙钟或外部服务。配置和有限日志同步进 OpenAPI / Go 校验，不新增数据库。施工 / 回收中不自动另派任务。F 已接入增量快照、世界 / 端点与承诺索引；大规模测量由用户执行。

## 现场作业与条件账本（E2c）

`incidents.ts` 从实际库存 / 供能 / 运行历史生成持续异常；`robotService.ts` 处理巡检、备件装载 / 消耗 / 实际返站退款与摄像头附件，复用 `robotFreight.ts` 的逐格 / 过境 / 能源 / 占格 / 返程。`workLedger.ts` 只由确认成功的转换记凭据，production.ts 探查条件、simulation.ts 在批次完成时原子消费。账本在主厂 industry，分厂 step 仅临时获得全球机器人和更新后的行业进度；随后删除其 robots / industry，避免复制保存或重复兑现。

WorkIncident、WorkReceipt、RobotService、camera 与 batches_completed 是同规则版本的可选存档扩展，旧档缺省空历史，原料 / 未用备件 / 携货 / 已安装附件仍作为真实资源保存。Go `work.go` 与客户端校验有界数量 / 时间 / JSON 结构；不重放客户端作业，不增加服务端模拟 / 表或改动账号与云版本约束。界面 WorkPanel 只消费确认事件和库存，不通过显示刷新生成凭据。异常列表供只读诊断复用，实际制造 / 物流窗口另由 Observations 采样；终局由永久制造记录确认。

## 机器人部署、补能与路径（E2a / E2b）

`local/robots.ts` 管理部署 / 召回 / 配置与实际补能，`robotRoutes.ts` 提供纯路径与返程能量估算，`robotFreight.ts` 在所有厂生产 / 物流和补能之后原子推进显式取送、装卸及跨区行程。全局实体统一保存在主厂 robots，当前投影提供列表，子厂不持久化副本；机器人只在实际装卸时扣收总仓库或设备缓存。`power.ts` 只将实付 kJ 写入有界 station_energy_kj。取消 / 编辑 / tick 均在 Worker 串行转换，失败不改变原世界。

机器人字段保持 format_version=1 的兼容扩展，当前共用仓库写 rules_version=3，旧档缺省空列表及无任务。可选 cargo / task / transit / returning / work_progress / completed_tasks 保存真实中途状态。Go `domain/robots.go`、`robot_freight.go` 与客户端共同校验归属 / 兼容站、当前授权厂、空格占用、载重 / 物品能力、工时 / 能源上限、任务阶段及过境余秒；部署与召回仍要求真实站邻格。嵌套任务必填字段不能缺省 / null，未知字段拒绝；已删除端点 ID 可保存，下一刻携货返站。服务器不重演路径或证明产量，未放宽 owner / Session / Origin / 云版本保护，无数据库迁移。

`RobotPanel` / `RobotTaskForm` 只读当前厂设备和远厂 WH 摘要，不为选单复制所有远厂布局。地图只显示确认的当前区坐标，过境时隐藏旧标记；无独立 RAF 或预测库存。当前完整世界由增量帧合并，路径仍为保守 BFS；独立测量入口已编译，没有进行百厂 / 五百机器人性能实测。

补能候选按归属厂 / 站索引，避免每座站扫描全部机器人；无机器人时跳过补能扫描。F 已减少空厂和未变布局复制，仍未执行百厂性能测量。

## 多厂区（E1）

同一 Worker 的 `local/world.ts` 持有起始厂和最多 99 个分厂，每半秒各推进一刻。初始 6 区，阶段数量上限 6 / 12 / 24 / 40 / 70 / 100。主厂保存唯一的行业进度 / 手工队列，分厂生产的首次制造成果合并到同一永久里程碑；手工队列每 tick 只推进一次。垃圾提取口可在各厂顶部安装，不设阶段数量上限。

所有 WH 共用主厂唯一总仓库，当前投影在任意厂显示相同库存；旧分仓在读取旧版本时合并。WH 入库、安装、补料和回收统一扣收，现场缓存、传送带、流体与能源网络独立，仍需实际物流。扩建从总仓库扣基础铁板 20 与简易支架 10。机器人跨区取送保留真实行程，但不再是玩家启动空分厂的前置。

主厂的可选 districts 记录完整分厂，active_district_id 记录显示厂区，分厂不得再次嵌套或保存独立行业进度。读取旧单厂存档时保留原厂 ID / 设备 / 库存并补入五座空厂。两端校验 owner、厂区 ID 唯一、同一 tick、阶段数量及单厂原有边界。无数据库迁移；云仍只有一份完整世界备份，正文上限扩为 64 MiB。

UI 只渲染选中厂的投影及简要厂区目录；Worker 普通 tick 返回增量帧，主线程恢复完整世界用于保存；百厂性能仍由用户测量，不能据此宣称满载百厂流畅。编辑携带发起时的厂区 ID，迟到的旧厂编辑在切换后拒绝，避免误写新厂。

## 组件与调用链

玩法扩展 A 至 F 已实现待用户统一验收，完整范围见 [gameplay-plan.md](gameplay-plan.md)。`scripts/import-gameplay.mjs` 从原案 JSON 导入稳定小写编号，生成唯一 catalog 与静态审计报告；浏览器和 Go 共用生成结果，原始设计案保持不变。

新增 `local/catalog.ts` 提供定义索引，`inventory.ts` 提供有界缓存操作，`industry.ts` 承担工作室预留、配方配置、手动搬料和永久里程碑，`fuel.ts` 管理与配方原料分离的燃料及可用热能。它们仍在同一个 Worker 串行事务边界运行。工作室 / 仓库视图保持三栏工作台尺寸，地图视图保留已有编辑器。

阶段 C 将物流抽到 `local/logistics.ts`；`transportConfig.ts` / `transportActions.ts` 负责配置和原子编辑，Go domain/transport.go 校验同一持久化字段。新增可选 belt.count、收据 count，旧档缺省 1；belt.progress 按定义允许 0～3，cooldown 允许 0～60。supplied_kw 是网络每刻派生的供能额度，发电由下述 power.ts 负责。

D1 已新增 `local/power.ts`，每 tick 清理派生供能、按物理导线格建图、分配真实燃料 / 电池能量、扣轴损并保存剩余工作能量。`production.ts` 统一配方前置、整批容量与实际能量判定，`utilityActions.ts` 处理启停、优先级、供能侧、电池模式和真实工作液启动。生产不再每次容量检查克隆库存，只在完成结算时复制产物缓存；这减少不必要对象分配，不代替性能实测。

新增可选 simulation.networks 供观察，MachineState 的 work_energy_kj / charge_kj / charge_remainder / medium 是实际保存资源；supplied_kw / generated_kw / powered / network_id 是派生状态，下一 tick 重建，不能当作存档授予的运行许可。保持 format_version=1 的兼容字段扩展，当前共用仓库写 rules_version=3，无数据库迁移。Go 与浏览器共同校验容量、数字边界和能源配置。

D2 新增 `local/fluids.ts` 定向整单位传输、`fluidConfig.ts` / `fluidActions.ts` 校验和原子操作。单介质容积独立于机器 100 件物品格；来源和容量统一预留，不能同刻穿过多个管格。真实锅炉可通过管线给分馏塔送蒸汽。液压功率网与物料管道分开，详见 simulation.md。

- `apps/web/src/game/local/state.ts`：本地工厂创建、存档校验、编辑与拆除回收；读取唯一的 catalog JSON 定义源。
- `simulation.ts`：无 DOM、网络、时钟和持久化依赖的确定性单刻转换 `step`，生产和物流的唯一实现。
- `simulation.worker.ts`：独立 Worker 串行处理 tick 与编辑指令。主线程每秒收到本机快照，不发送网络生产快照。
- `runtime.ts`：生命周期、同账号标签页独占锁、在线许可、Worker 指令、串行保存队列、云备份与冲突选择。
- `storage.ts`：IndexedDB 完整存档事务。事务完成之后才显示保存成功；不使用 localStorage 保存游戏数据或凭据。
- React / DOM / CSS / SVG：保留编辑器、HUD 和共享 RAF，普通 / 节能绘制约 60 / 15 FPS。
- Go `httpapi → application → domain / repository`：认证、Origin / JSON 边界、结构校验与云存档事务。服务器没有生产循环和建筑编辑接口。

运行链路：`编辑 / 0.5 秒计时 → Worker → 完整本机状态 → UI / IndexedDB`。

备份链路：`本机一致快照 → Cookie + 绑定会话 → 唯一云存档事务 → 仅更新本地备份元数据`。上传期间的新 tick 或编辑不能被响应中的旧快照覆盖。

## 本机时钟与原子操作

玩法存档仍为 format_version=1，新的 rules_version=2 增加 simulation.industry（阶段、永久里程碑、累计制造数、可选工作室队列）、机器可选 fuel / energy_kj、configuration.recipe_id。客户端读取 rules_version=1 时无损补入初始阶段，保留当前目录内的机器、库存、tick 和 ID；含已移除测试内容的存档拒绝读取并保留原档，当前本机写入与上传使用版本 3，共用总仓库升级见本文开头。服务端兼容接受 1/2/3 三种规则版本，现有数据库迁移无需修改。

1 tick = 0.5 秒，`simulationTime.ts` 共用时基；生产进度 / 冷却用秒、带载荷进度用整数 tick，能源以精确 0.5 kJ 结算。物料管道与机器人现场移动每半秒动作一次，机器人装卸 / 作业与过境保留秒级节奏。页面隐藏 / 最小化 / 切换浏览器 Tab 继续生产。短暂计时延迟按到期时间顺序执行普通单刻转换，单次最多 5 刻；唤醒间隔超过 2500ms 时暂停并重新校验，恢复重新等待一个调度间隔。关闭、休眠、浏览器冻结、断网或在线许可失效仍暂停，不产生离线收益。

Worker 消息队列串行执行编辑和 tick。每次转换先创建独立的新状态，成功才替换当前状态；失败保留原状态。移动保留实例 ID、库存与进度，删除与回收属于同一次转换。revision 每次成功编辑 / tick 增加。

IndexedDB 数据库为 `bakafactory-client-v1`，按不可变账号 ID 隔离。一个记录包含格式 / 规则版本、完整工厂（布局、配置、模拟、总仓库）、云版本、上次上传 revision 和保存时间。编辑后保存，每 5 秒游戏时间（10 tick） 自动保存；切后台和正常卸载尽力保存。所有写入按提交顺序排队，最后一笔事务结束后才释放标签页锁。不能保证浏览器强制退出时执行最后保存。

本地读写失败或格式损坏不会静默清档。写失败暂停生产和编辑，玩家可重试保存；保留内存中的当前进度。申请浏览器持久存储属于尽力保护，不能抵消玩家主动清除网站数据。

## 在线、会话与多标签页

每次成功登录在同一事务内撤销该用户其他 Session，然后创建新 Session。账号仍用 Argon2id 和 HttpOnly Cookie。游戏首次通过 `POST /api/v1/game/heartbeat` 绑定会话标识，此标识不能用于登录；后续心跳和云存档请求必须保持绑定。这样同浏览器 Cookie 被另一次登录替换时，旧标签页不能借用新 Cookie 继续上传。

Worker 初始化后每约 10 秒通知主线程请求心跳，不携带工厂或库存；仅初始化阶段用主线程重试定时器。隐藏时不停止心跳，相同速率的续期不重置模拟计时器。请求超时 8 秒，每次许可最多 30 秒且从发起请求时计时；Worker 独立检查许可到期，主线程卡住时也不会无限运行。收到 401 立即暂停并返回登录；网络失败暂停并重试。HTTP 轮询存在有限检测延迟，不承诺新登录时旧画面瞬间消失。旧会话的上传会被服务器即时拒绝。

同浏览器同账号用 Web Locks 独占运行；另一个标签页提示关闭原页面后重试。标签页锁要求支持 Web Locks 的浏览器及安全上下文。账号切换通过组件 owner key 隔离，不共用运行状态。

## 唯一云存档

账号会话默认有效 30 天。网页打开 / 刷新时既有 `GET /api/v1/me` 通过应用层续签：仓储在同一事务内核验会话未过期、延长 `sessions.expires_at` 并读取账号，HTTP 层同步刷新 HttpOnly Cookie。保留原 token 和游戏绑定标识，旧有效会话可直接延长；心跳仍只核验在线许可。无新增接口、字段或 migration，失效会话不重建，详见 [账号机制](auth.md#密码与会话)。

| 表                                                                       | 当前用途                                               |
| ------------------------------------------------------------------------ | ------------------------------------------------------ |
| users / sessions                                                         | 账号与每账号一个有效登录会话                           |
| cloud_saves                                                              | owner_id 主键；完整存档 JSON、服务端 version、saved_at |
| schema_migrations / application_metadata                                 | 已发布迁移校验与初始化元数据                           |
| factories / building_instances / factory_simulations / player_warehouses | 遗留表，仅保留原记录，不再读取为新游戏或推进           |

新增 `006_client_saves.sql`，不修改 001～005；已有多个会话只保留最新一个并增加唯一索引。保留账号和所有旧工厂原始记录，新架构不导入旧进度；首次没有新本地 / 云存档时从空工厂开始。

云端每账号仅一份存档，自动 / 手动上传都覆盖这一行。每 30 分钟检查是否有新进度；失败后按一分钟间隔重试，心跳恢复不额外传送整厂数据。手动上传立即执行。本机定期生产不会让云数据自动变化。

登录时优先有效本机存档，没有本机工厂存档（含仅有空占位记录）才自动恢复云备份。始终读取一次云存档核对其版本；已有本机记录而云版本不同则暂停并提供“保留本机并覆盖云端 / 恢复云存档”。恢复需要明确确认。上传携带 base_version，服务器不匹配返回 409，不按客户端时间或 tick 判新旧。首次没有任何云存档时 base_version=0。

云上传的 Session、owner 和云版本在同一 SQLite 事务内检查，避免被撤销会话的在途写入。备份确认只改变云版本 / 上传 revision，不回写运行中的游戏状态。数值使用 JavaScript 安全整数范围，上限为 9007199254740991。服务端校验格式、大小（64 MiB）、定义、坐标、容量和版本；默认信任单人玩家提交的数量，不证明真实产量，也没有增长速率反作弊。

## API 与运行边界

- `POST /api/v1/game/heartbeat`：会话绑定、轻量在线校验。
- `GET /api/v1/game/save`：本账号备份或 null。
- `PUT /api/v1/game/save`：校验会话、结构和 base_version 后替换唯一备份。
- `/api/v1/definitions`：登录后可读定义；浏览器运行直接打包同一 JSON，不逐 tick 请求定义。
- 原 `/api/v1/factories...` 接口已移除，返回 404。

API 源为 [openapi.yaml](openapi.yaml)，类型必须由 `npm run generate:api` 生成。写请求继续要求允许的 Origin 和严格 JSON，错误响应不清除 Cookie，避免旧请求的迟到错误擦掉新登录 Cookie。

仍为单实例 Go / SQLite 服务。玩家必须联网并校验账号；没有离线启动、PWA、WebSocket、跨设备库存合并、历史云存档槽位或离线补算。未来补算可分批调用纯 `step`，需要另做性能测量、时间上限和进度反馈。
