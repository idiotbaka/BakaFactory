# 地下传送带出入口

## 配方与范围

P2 开放，在自动装配台 M08 使用简易齿轮 ×2、基础铁板 ×2，每批 12 秒产出一套。工作室沿用原有手工工时规则（本配方为 6 秒），需先制造自动装配台，才能开放工作室中的手工装配台分类。没有额外任务或里程碑门槛。

一套安装两个单格端口，安装 / 回收只扣收一套道具。无需动力，出口缓存最多承载一种固体的一个批次、最多 6 件，出口每格 1 tick（当前为 0.5 秒）；真实数量仍受上游带 / 投料机批次限制，不自动攒批。散装流体不走此设施。

规则由 `scripts/import-gameplay.mjs` 适配导入，保留原案 JSON。新增物品 `d0001`、建筑 `underground_belt`、配方 `web_underground_belt`；现有物品和配方编号不变。

## 放置、编辑与显示

地图批量框选会自动补齐配对另一端；整组移动可沿任意坐标轴平移，保留两端相对位置、原方向和距离。下述单端长按仍只沿原轴线调整；批量回收仍每对只返还一套及实际缓存，详见 [批量编辑](batch-editing.md)。

1. 在建造阵列“物流”选择该道具，用 R / 右键设置方向。
2. 第一次点击空格只标记半透明入口，不扣库存、不建实例、不写存档。预览期间不占用逻辑地图，运行层在最终确认时再次检查。
3. 沿入口箭头的直线方向点击出口，两坐标距离须为 1～8 格（距离 8 即中间留 7 格）。东西向和南北向都支持；两端必须空闲，地下中段可穿过任意建筑，也可与其他地下路线交叉。
4. 第二次点击有效时，Worker 原子创建两个互相引用的端口并扣一套道具。缺料、占格、蓝图 / 机器人占格或堵住机器人安全返程时整笔失败，保留入口预览便于改选出口。成功后可连续放置下一对。
5. Esc、选择 / 取消、切换建造工具或切厂会取消尚未完成的配对；不扣道具。
6. 已安装端口可长按拖动，但只能沿配对的原水平 / 垂直轴线调整，不可越过另一端或超过 8 格；非法落点显示红色并拒绝保存。两端保持共同朝向，更改方向须回收后重建。
7. 选中任意端同时高亮另一端，并显示静态虚线配对提示。检视显示入口 / 出口、另一端坐标与距离。回收任意端同时移除两端，返还一套道具及出口实际载荷。

端口采用 30×30 整数 SVG：深色带面、金属护罩、警示条与粉色入口 / 青色出口箭头。物流图鉴和地图使用 SVG，物品图鉴、仓库、配方等使用独立的 128px 透明像素图。预览和配对线不新增 RAF 或持续装饰动画。

### 四向坐标与箭头

地下端口与普通传送带共用朝向：地图世界坐标的 y 向上增大，屏幕 y 向下增大；SVG 的正角度为屏幕顺时针。放置预览、已安装入口 / 出口、图鉴图形及出口载荷动画必须一致，地下端口不再另作反向旋转。

| 朝向    | 角度 | 出口位于入口的世界坐标方向 |
| ------- | ---- | -------------------------- |
| 右 / 东 | 0°   | x 增大                     |
| 下 / 南 | 90°  | y 减小                     |
| 左 / 西 | 180° | x 减小                     |
| 上 / 北 | 270° | y 增大                     |

此前竖向反转来自图形和载荷动画的负角度特例，放置 / 运输 / 读档校验的世界方向本身正确。修复仅统一显示：不翻转已保存的朝向、不交换出入口、不改配对、库存或运输时序，也无需迁移。已存在的竖向线路会按其真实运输方向显示箭头。

## 运输与守恒

示例：`地面带 → 入口 ···（地下）··· 出口 → 地面带`。入口只从箭头后方收货，出口只向前方主动送货，不从地面接收。输入可以来自地面带、投料机或仓库输出。机器与带之间仍遵守原有投料接口规则。

地下段是一条路由边：旧上游载荷进入入口的同一次转换中，直接进入配对出口的真实缓存。入口不持有物品，没有地下路径、地下运输计时或地下占格检查。出口沿用正常带的地面出料时序，新收到物品不会在同刻继续跨出下一格；这不额外收取地下行程时间。

规划器对实际出口预留容量，并继续使用原有带占用依赖判定。出口堵塞或禁用、入口禁用 / 过滤拒收时保留来源；出口的旧载荷同刻完整离开才允许接收下一批，部分拆批不算腾空。允许快慢带拆批，库存不复制、不丢弃。地下跳转不生成穿过地上建筑的飞行收据；原载荷身份保留，出口从自身地面位置绘制，动画不参与结算。

## 持久化与边界

两端均为 `underground_belt`，在 `configuration` 中保存 `underground_role`（entry / exit）与 `underground_peer`（另一端实例 ID）。显式配对不根据距离重新匹配，多条平行、重叠或交叉线路不会串线。

客户端读档与 Go 云备份校验共同检查同厂、相互引用、相反角色、同向、前后距离、P2 门槛及空入口状态；孤立端、错配、跨厂和非法载荷拒绝并保留原档。通用单端建造和机器人单格施工均禁止生成该设施。本轮不扩展机器人为成对施工；其施工列表不提供此道具。

沿用已有任意 JSON configuration 和带缓存结构，没有协议字段变更、数据库迁移或规则版本升级。旧存档不含端口时行为不变；唯一总仓库与各厂现场独立规则保持。

## 验收（待用户执行）

启动项目使用 `npm run dev`。自动回归代码已补充，执行命令：

```bash
npm test
```

手动检查：

1. P1 的物流建造列表不可建；P2 在自动装配台 / 工作室找到配方并实际制造一套。
2. 选择道具，在 `(-4,3)` 点击入口。确认只有半透明预览，库存、建筑实例数不变；按 Esc 或切工具后预览消失。
3. 再选入口 `(-4,3)`，点 `(5,3)`（9 格）、`(4,4)`（不共线）或已占用格，应拒绝且不扣道具。点 `(4,3)` 成功，库存减一、实例增加两个。
4. 在入口后方 `(-5,3)` 接地面带、出口前方 `(5,3)` 接地面带，沿原有机器 → 投料机或 WH 输出方式供料。中间可摆其他建筑；地下物品直接抵达出口，不在地上跨线飞行。
5. 堵住出口下游，确认货物停留且源头等待；释放堵塞后恢复。用大批次带转入初阶带检查拆批守恒；禁用任意端、过滤不匹配时不得穿透。
6. 长按入口沿同一行移至 `(-3,3)` 可成功；拖到另一行、越过出口、距离超过 8 格或占用格均应拒绝。出口同样检查。换成南北朝向重复验收。
7. 搭建相交、重叠及平行的地下路线，使用不同物品确认按显式配对送达。只有端口占用地面格，中段不阻挡普通建筑或机器人。
8. 带载荷移动出口，确认载荷保留；删除入口或出口均同时回收整对，仓库只返一套及真实载荷。材料不足时整笔安装失败。
9. 在分厂安装，确认只扣共用总仓库且其他厂库存投影一致。刷新本机存档、上传 / 恢复云备份后检查配对与载荷保留；不要为验收删除账号或数据库。

竖向修复专项：在空闲位置选朝下（90°），入口 `(-4,4)`、出口 `(-4,-4)` 应成功，入口上方为后方、应拒绝；朝上（270°）时反过来，入口 `(-4,-4)`、出口 `(-4,4)` 应成功，入口下方应拒绝。接入地面带供货，检查箭头、出口载荷移动及实际出料都朝同一方向；再重复东西向放置、移动和刷新。自动测试覆盖四向图形 / 动画、一上一下的两次点击、明确坐标的放置 / 反向拒绝 / 运输 / 读档，实际执行状态见 [进度](progress.md)。
